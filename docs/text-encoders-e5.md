# MiniLM 与 E5：固定 72 题的离线对照

2026-10-07。**本轮不采用 E5。** 在当前混合格式语料及原切块／融合链路上，E5 的 Top5 由 MiniLM 的 63/72 降至 34/72，耗时也增加。进一步排查没有发现前缀、分词丢字、池化或向量维度接错；一个最小反事实实验确认，中文元数据标签能够使无关作品超过正确英文作品。这个发现不能被概括为“E5 普遍不如 MiniLM”。

## 控制变量

同一批 300 件 V&A＋12 件 AIC，共 3021 个原始切块。保持逐行按 220 字符包装、作品标题前置、原 BM25、每路 Top25 切块、RRF k=60、融合保留 25 切块、去重展示 5 件作品不变。

两组都没有接入上一轮实验中文字段或 BM25F；字段文件哈希保持不变，仅作冻结边界。此次只比较编码器，不能称为“BM25F＋E5 完整新架构”的结果。

- MiniLM：`paraphrase-multilingual-MiniLM-L12-v2`，修订 `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`，384 维，原输入无前缀。
- E5：`multilingual-e5-base`，修订 `d128750597153bb5987e10b1c3493a34e5a4502a`，768 维；问题加 `query: `，资料加 `passage: `，归一化输出，符合[官方模型说明](https://huggingface.co/intfloat/multilingual-e5-base)。
- 分别建立向量索引，禁止混用维度；所有模型在 CPU、4 线程下运行，文档批量 32。问题逐条编码，两组交替先后执行。没有 hash fallback、付费模型调用或资料外发。
- MiniLM 文档向量重算与原索引数值一致，80 道题的前五列表均与已有报告完全一致。E5 原生上限 512 token、MiniLM 128，本轮文档最高分别 85/83、问题最高 29/26，均没有截断。

题目是旧 50 道＋新 22 道有目标的开发题，另有 8 道模糊观察题。沿用原冻结文件，不改题、不补中文、不调参数。它们未完成人工复核，不能当真实用户准确率。

## 结果

| 指标 | MiniLM | E5 |
| --- | ---: | ---: |
| 总 Top1 | 53/72 | 31/72 |
| 总 Top5 | 63/72 | 34/72 |
| MRR@5 | 0.789 | 0.444 |
| dense 前 25 切块含正确作品 | 68/72 | 40/72 |
| 全部中文 Top5 | 32/41 | 3/41 |
| 全部英文 Top5 | 31/31 | 31/31 |
| 新作品中文 Top5 | 8/11 | 1/11 |

相对 MiniLM，E5 没有修复原先的 Top5 失败，却新增 29 条 Top5 退化；此前 G01、G05、G11 三件排名不足的作品也未改善。E5 的 41 道中文问题中，40 道把 AIC 作品放在第一位，而这些问题的预期作品均来自 V&A，显示了强烈的来源／格式偏向，但本身不能单独证明原因。

本地实验链路 P50/P95：MiniLM 51.16/56.77 毫秒，E5 104.03/115.18 毫秒。不含 HTTP、回答生成、图片识别或额外的全排名诊断，不是网站 SLA。

同一文档批次编码约 11.90 秒与 44.27 秒。E5 权重文件约 1.11 GB；同进程新增 E5 和索引时工作集增加约 1.41 GiB，受分配器及保留 MiniLM 的影响，不能当独立部署峰值。

## 为什么没有直接认定为“模型不好”

使用本地两作品、随后两切块最小复现：问题“海神与特里同”，正确来源为海神讲解，无关来源为《睡莲》的编号行。两次结果一致：无关编号行分数约 0.814，高于正确英文片段约 0.783。此失败已保留，没有通过改题删掉。

依次核对三个假设：

1. **池化接错？** 用官方说明的 attention mask＋mean pooling＋L2 normalization，直接调用同一个底层 Transformer，与适配器的向量最大绝对差约 `1.01e-7`，向量余弦约 1。此复现未发现池化偏差。
2. **中文丢字／前缀错误？** 解码仍为完整的 `query: 海神与特里同`，未知 token 为零，模型处于 eval 状态。文档均有 passage 前缀。没有发现此类接入错误。
3. **中文标签造成干扰？** 保留正确片段、英文词和数字，仅移除无关编号片段里的中文标签后，其分数降至约 0.770，正确片段重新排第一。改用英文问题也恢复正确。仅将两作品改为整篇原文并未恢复，说明不能简单把问题归为“块太短”。

这是一个局部因果探针，支持“标签语言和资料组织是贡献因素”；不证明其解释了全部 29 条退化。公开字段标签和 V&A 纯英文讲解的格式不同，在这次实验中放大了 E5 的排序偏差。正确的处理应先规范语义索引输入，而不是降阈值、硬编码作品名或把坏题移出评测。

没有确认需要修复的适配器 bug，因此没有把两切块语义失败加入常规 CI 作为必过断言，也没有声称原失败已经修好。最小复现、诊断和原报告保留在本地私有目录，网站仍使用原链路。

## 代码、测试及复现

- `text_encoder.py` 提供独立的编码器实验适配：查询／资料分开编码，检查维度、非有限值及归一化，明确禁止静默回退。未接到线上 `MuseumIndex`。
- `download_e5.py` 仅下载固定修订的公开文件，校验大小、官方大文件 SHA-256，并记录本地清单；模型缓存被 Git 忽略。
- `evaluate_text_encoders.py` 检查冻结文件、旧候选列表和模型文件哈希，保存逐题新旧候选、dense 排名、时延、修复和退化列表。
- 253 项后端测试通过，新增 5 项覆盖前缀、中文、原 MiniLM 输入、维度隔离、无效向量与空批次。真实模型正确性另由本轮本地对照和官方池化比对验证，不能只凭合成单测断言模型效果。

```powershell
$env:PYTHONPATH='backend'
.venv/Scripts/python.exe scripts/download_e5.py
.venv/Scripts/python.exe scripts/evaluate_text_encoders.py
```

需要既有私有语料、四套问题及历史报告。结果脚本拒绝覆盖已存在文件；公开克隆没有这些私有材料，只能运行合成单测。

## 下一步

先规范语义输入：让编号等结构化元数据保留在字段索引，避免无语义的独立标签行与正文同等参与 dense 排序；原始来源内容仍完整保留供引用核对。作为另一组实验，对同一批 72 题分别记录修复、退化与模糊查询属性表现。

数据输入稳定后，再做作品级融合与重排。当前继续使用 MiniLM；不扩大到 1000 件，不把这一轮结果写为上线改善，也不因为 E5 已下载就启用它。
