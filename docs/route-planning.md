# 有来源的参观路线 v1

## 用户任务

游客在对话里点击“路线”，或提出“我有 30 分钟，喜欢雕塑，帮我规划参观路线”。系统先展示覆盖的博物馆、馆区及偏好确认卡，再根据确认后的时间、兴趣、起点和无台阶要求计算参观顺序。

路线卡展示起点、各站内容、移动与停留估计、经由的展厅、来源和核对日期。游客可以“跳过此站，重新规划”，也可以调整偏好；有已接入讲解库的作品时，可继续听讲解。

按用户反馈，将早期点线示意替换为真实平面图上的单层导航案例。馆方原始底图不重绘，SVG 仅叠加一条人工核对可见通道的固定路径、终点和“你在这里”标记。支持播放／暂停、拖动进度、回到起点、展开地图和放大跟随。只有当前位置与行走速度为模拟，不调用设备定位。此案例独立于偏好规划结果，不宣称可为任意起终点生成实馆导航，也不添加未经核实的设施点位。

优先处理四类日常寻路：找出口、楼梯／电梯、厕所和服务台。既可在路线卡点击快捷入口，也可直接在聊天框提问。设施位置从同一份有来源的资料快照读取，不通过大模型生成。已知设施位置不等于已知到达通道：首版提供位置说明、限制和馆方位置链接；没有当前位置和通道证据时不宣称“最近”，也不生成逐步走法。

## 技术和产品边界

- 复用 FastAPI、Next.js、现有 DeepSeek 客户端，不增加服务或付费地图依赖。
- 路线图来自独立、版本化的资料快照。藏品介绍不能用于推断展位，照片识别也不能用于自动定位。
- 模型只提出时间、兴趣、白名单起点等偏好，用户确认后才计算路线。超时或输出无效时保留本地提示与手工选择，地图和通道不由模型生成。
- 图中每条有向连接都有来源。Dijkstra 计算已知连接上的移动代价，小规模枚举比较时间预算内的参观组合；兴趣匹配优先，同分时优先多看展厅、再减少估计时间。此处的最优只针对这个有限图和项目估计，不能宣称实馆最短或最快。
- 每次计算均计入途经展厅的移动时间。跳过某站表示不停留，不代表不能经过。已关闭节点不得作为中转；未提供的反向连接不自动补全。
- 无台阶要求为硬约束，只有明确标注可无台阶通行的连接才可使用。资料不足时拒绝承诺并提供馆方地图，不回退到包含台阶的路线。
- 起点由游客确认；当前展厅仍可安排停留，无需跨厅移动。已看过的展厅可跳过。时间不包含入馆排队、休息和从末站离馆的路程。移动和停留分钟数均为项目估计，未经现场测量；不提供 GPS、实时拥挤度或闭馆感知。
- 路线快照过期后暂停推荐；必须重新核对资料，不能仅修改日期来延长有效期。

## 配置与回退

通过本地 `.env` 的 `MUSEUM_ROUTE_MANIFEST` 指向 JSON 快照，重启后端生效；移除此配置即可关闭路线推荐，问答与拍照保留。馆方素材及本地路线数据不随 GitHub 发布。

真实地图案例单独使用 `MUSEUM_FLOOR_DEMO_MANIFEST`。结构见 `backend/app/museum/floor_demo.py` 的 `FloorCase`：包含来源、署名、核对日期、视窗、原始图片相对路径与像素坐标、路径点及提示。图片仅从清单所在目录的白名单 PNG 读取，接口不返回本地文件路径；图片缺失时不展示路线。清单与图片放在忽略目录中，移除配置即可关闭地图案例。实际展厅连通性经过底图目视核对，未进行现场通行或定位精度测量。

快照结构由 `backend/app/museum/routes.py` 中的 `RouteMap` 定义：`sources` 保存来源；`nodes` 保存展厅、楼层、兴趣和停留建议；`edges` 保存有向连接、移动估计、方向说明和无台阶状态；`checked_at` 与 `valid_days` 控制时效。源码测试中的地图完全虚构，可用于理解配置，不得用于实地参观。

当前实现最多 8 个可参观节点，以限定计算量和资料核对范围；每个新馆区应单独核对并维护图，不把不同博物馆的作品拼成一条路线。

## 记录与评测

路线复用 `/api/museum/chat` 的会话鉴权、并发保护、请求编号防重、反馈归属与删除机制。`action=route` 的执行记录包含地图哈希、规划器版本、最终确认偏好、计算结果及偏好提取方式。路线状态与艺术史问答上下文分开，路线文字不充当文物事实证据。

自动化使用合成地图检验时间预算、兴趣改变、跳过停留但仍计移动、关闭中转、无障碍未知、反向连接缺失、来源缺失、快照过期、模型伪造节点、请求防重和跨会话反馈隔离。真实地图验证另存本地，不把这些工程检查当作真实游客的路线满意度或 A/B 成效。

真实体验评审重点：是否容易确认起点、路线是否太赶、从一站到下一站是否能看懂、跳过一站后的重算是否符合预期，以及无障碍资料不足时是否足够明确。
