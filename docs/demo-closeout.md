## 固定配置与复查

从仓库根目录执行，服务应已启动：

```powershell
$env:PYTHONPATH='backend'
.venv/Scripts/python.exe scripts/freeze_demo_release.py verify --release muse-demo-20261010
```

`matches: true` 表示与本地冻结清单一致，不代表自动质量验收通过。脚本不会访问模型供应商，不输出 `.env` 内容；同名冻结目录不能覆盖。将来另立版本可用 `freeze --release <新的英文版本名>`。

私有快照位于 `.runtime/releases/muse-demo-20261010/`，其中 `config.env` 含真实凭据，不能上传、截图或发给面试官。`manifest.json` 保存源文件及资料清单哈希和健康版本；它不复制模型权重、原始图片或数据库，也不证明已安装依赖永远不变。应保留现有本地模型、数据、锁文件及独立 MongoDB 备份。

演示前复跑自动检查：

```powershell
$testDir=Join-Path (Get-Location) ('.runtime/acceptance-' + [guid]::NewGuid().ToString('N'))
.venv/Scripts/python.exe -m pytest backend/tests -q --basetemp $testDir -o cache_dir=.runtime/pytest-cache-closeout
Push-Location web
node --test tests/*.test.cjs

```

## 恢复与启动

当前网站无需重启。若之后仅修改配置需要恢复：先停止本项目的后端进程，另存当时 `.env`，将私有快照 `config.env` 复制回 `.env`，使用 `scripts/start-backend.ps1` 启动后再运行 `verify`。代码或数据也变化时，单独恢复配置不足以通过检查；不要运行 `git reset --hard` 丢弃工作区。数据库不随配置恢复清空。

需要从关闭状态启动时，依次运行 MongoDB、后端、前端；后端和 MongoDB 保持仅监听本机。手机演示的前端命令为：

```powershell
# 各服务分别在终端启动，已有服务时不要重复运行
powershell -File scripts/start-mongo.ps1
powershell -File scripts/start-backend.ps1
# 在另一个终端进入 web 目录
npm.cmd run dev -- --hostname 0.0.0.0 --port 3000
```

这仍是手动启动及恢复流程，不是自动部署、灰度发布或生产级容灾。GitHub CI 负责测试和构建，不会把代码自动部署到馆方。

## 保留的已知限制

1. 海神背面仍可能误列参孙为待确认候选；图库有正确作品不保证核对正确。未展示为自动确认身份，但游客误选的风险仍存在，不能把“有人工确认”写成已经消除了误识别。
2. 补背面参考图的实验只改善局部案例召回，未通过最终身份验收；匿名核对模块仅离线准备，未接网站。
3. 资料过短、未知作品或错误前提应说明不足；并非每件作品都有官方讲解词或足够的儿童／深入讲解素材。
4. 路线是限定区域的确定性建议，地图移动点为模拟。工作人员与文保页是独立模拟，不接真实人流、传感器、内部文保资料或角色权限。
5. 仅验证本地单服务进程；未验证万人在线、公开互联网安全部署、真实游客在线 A/B 或全库识别准确率。

下一次开发只修验收发现的阻断问题。若现场局部识图仍不理想，演示保留失败、候选和补拍过程；不通过偷偷替换测试图片、下调阈值或改变历史答案来提高分数。

## 2026-10-16 用户验收阻断修复

本节是后续修复记录，不改写上面的 10 月 10 日历史结果。运行提示词更新为 `museum-grounded-v14-separated-spans-json-bounded-v1-review-entailment_v1`。

- T01：用户反馈部分作品没有中文稿。预置讲解库仍只覆盖部分作品；无预置稿时使用模型依据馆方原文生成，资料不足时仍应说明边界。本轮验证了没有预置稿的 Chair 中文讲解，不代表已逐件验收全库中文质量，也没有补造官方讲解稿。
- T02：问题并非编号索引不支持小写，而是聊天请求携带上一件已选作品，绕过了编号直达。已让完整且命中的编号优先发起新作品确认，清除旧作品与照片上下文；部分编号或普通追问仍保留原有边界。大小写编号均验证命中 `va-o77966-flower-pyramid`，后续制作者、年代、材质由对应编目直接回答，专名和部分字段仍保留馆方英文。

验证：针对性 66 项回归及后端完整 601 项测试通过（保留既有 Starlette 弃用警告）。通过运行网站的真实 HTTP 接口完成 9 条请求：T03 查找、简明讲解、装饰追问、儿童版，以及 T02 大小写编号、制作者、年代和材质；均达到对应状态和来源核验要求。T03 四条实际调用模型，响应约 6.1–11.7 秒；T02 五条为确定性字段路径，模型调用为零。这些是修复回归，不是独立盲测准确率。

## 2026-10-16 最后收尾：T10 / T12

本轮冻结功能范围，不再扩库或替换视觉模型。提示词版本为 `museum-grounded-v15-bounded-fact-reselection-bounded-v1-review-entailment_v1`。

- **T10 证据提取**：用户追问“它有什么值得观察的细节”时，模型将一段英文原文改动后当成逐字引用，四条候选事实因此整体未通过校验。新增一次有上限的重新提取：提供原始资料、被拒草稿和明确错误，重新进行来源、连续引文与 value 校验；两次均失败则继续拒绝生成。完整记录两次选择与耗时，不做模糊纠正或降低最终语义核验标准。正常提取没有新增调用，失败最多增加一次调用。
- **T12 语音生命周期**：收到最终转写时即清理录音实例，不再依赖浏览器一定发出结束事件；旧实例回调不能修改新录音。停止后两秒没有结束事件会复位，单次录音最多等待三十秒；权限失败、启动异常、组件禁用和离开页面也释放实例。文字仍由用户确认后发送，未新增录音存储。
- **T11 范围**：官方地图入口可用，不代表已验证全馆实时路线或室内定位。当前路线仅限已有图数据与约束，无法满足时应说明不可规划；工作人员、文保、人流与移动点仍为模拟。

自动检查：后端 **604 项**、前端 **20 项**通过；Next.js 生产构建通过。语音新增五项测试控制实际组件的浏览器事件顺序，覆盖一次成功后再次启动、过期回调、权限失败、停止无结束事件、禁用及卸载清理。这些测试不是 iPhone 麦克风验收。T10 测试覆盖重新提取成功、再次失败与返回空证据，并保留逐字引用和语义拒绝测试。保留既有 Starlette 弃用警告。

### 用户最后复测（约五分钟）

先刷新一次加载新版；之后语音测试过程中不要刷新。

1. **T10**：选择《海神与特里同》，依次听简明、儿童、深入讲解，然后问“它有什么值得观察的细节”。查看中文回答及所附依据；若仍未通过，记录时间和作品名。再问“制作者当天早餐吃了什么”，应说明资料不足。
2. **T12**：语音输入三次不同的问题，每次确认转成文字后发送，再开始下一次。另试一次手动停止后重新录音。应不需刷新；若失败，记录浏览器、时间、按钮显示“语音”还是“停止”以及提示文字。
3. **T11**：打开官方地图，确认地图/模拟边界仍清楚；没有可行路线时不应凭空给出路线。

### 可用于项目介绍的边界

这是千件规模馆藏的本地作品集演示，具备文字检索、来源核验、拍照候选与补拍、讲解、MongoDB Trace/反馈和模拟业务页。不能写成博物馆实际部署、全库识别通过、真实客流分析、在线 A/B、万人并发或正式文保系统。用户的局部花器、海神背面首拍失败记录保留：补拍能完成任务不等于首拍识别成功；库外图片没有确认身份也不等于相似推荐质量已通过。面试材料应分别报告实现、自动回归、真实模型回归、用户验收和模拟功能。
