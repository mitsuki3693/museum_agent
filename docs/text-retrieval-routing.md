# 文字分流检索：编号验收与后续分组实验

2026-10-07。本轮完成 **完整馆藏编号精确分流**。中文结构化字段、BM25F、E5、作品级加权 RRF 和 Reranker 尚未接入，按下面的分组分别验收。图片处理与 300 件候选库的启用状态均不改动。

## 已实现：完整编号直达

`MuseumIndex` 根据原始 `fields.accession_number` 建立 canonical key → source IDs 索引。对完整裸编号做 Unicode NFKC、大小写统一及限定分隔符清理；例如 `C.2359-1910`、`c 2359 1910`、`C-2359-1910`、全角变体都可匹配。

- 只比较完整字段，不做前缀、编辑距离或“从任意句子中抽取数字”式的精确命中。编号嵌在自然语言问题中目前仍走原检索。
- 删除分隔符可能使原本不同的编号发生冲突，故一个 key 保留全部对应记录。不会只留第一条，也不假定不同馆的编号全局唯一。
- 完整命中绕过语义向量与 RRF，仍回查资料的 active 状态与 source_hash。准确记录失效时不会用相似记录代替。
- 明确指定作品的调用保留原范围；直接在聊天中输入新完整编号则清除上一件作品的隐含上下文，进入新作品确认，不让模型改写编号。
- 聊天结果使用现有候选确认卡，不调用大模型进行“猜是哪件”；多条记录让用户选择。Trace 记录 `retrieval_route=exact_accession`，其余为 `natural_language`。
- 部分／错误编号不被标为精确命中，按原逻辑进入模糊检索。此处不声称生成层对所有错误编号都会正确拒答。

## 同一 300 件候选库上的实测

使用固定的 [300 件验收](scale-300-evaluation.md) 数据；没有更换文本模型、语料或切块。

| 项目 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 新增 200 件原始编号 Top1 | 170/200 | 200/200 |
| 新增 200 件原始编号 Top5 | 197/200 | 200/200 |
| 原编号／空格／连字符／紧凑形式 | 未测 | 800/800 Top1 |
| 200 个错误编号＋200 个部分编号 | 未测 | 0 个误走精确命中 |
| 原有文字题（含 4 道模糊题） | 44 题已有记录 | 44/44 候选列表和顺序不变 |

800 次包含同一编号的格式变体，不能当 800 个独立用户样本。真实 300 件候选库没有归一化冲突；合成测试额外验证不同原编号映射到同一 key 时必须保留全部记录。

MemoryStore 的编号查询中位约 0.020 毫秒，最近秩 P95 约 0.023 毫秒；这是单机内存查找＋来源回读测试，不含 HTTP、MongoDB、生成或并发，不能写成网站 P95。普通文字的原有失败也全部保留，**本轮没有改善中文语义检索**。

8 项新回归先失败后通过，覆盖误入模糊排序、格式变体、归一化冲突、失效／版本变化、上下文范围及零模型调用。全部后端测试 231 项通过。没有调用付费 API，没有新增手机端实测；运行中的服务须加载新代码才会生效，未将 300 件候选库切到网站。

复现脚本：`scripts/evaluate_accession_routing.py`。私有结果：`eval/private/accession-routing-v1.json`，保存输入编号、候选列表、格式控制、时延、44 题前后列表及原评测哈希，拒绝覆盖旧结果。数据不随 GitHub 发布。

## 下一组：中文字段与 BM25F

馆方原始资料不覆盖。另建检索用字段：`title_zh`、`aliases_zh`、`subject_zh`、`appearance_zh`、`material_zh`；逐字段记录源作品 ID、原文哈希、支持片段、整理方式、版本、审核人／状态。AI 整理不能自动标为人工审核，检索辅助文本不能自动升级为回答引用依据。

字段权重从 5、4、3、3、2，原文 1 开始冻结。BM25F 应先对各字段长度归一化后的词频赋权求和，再做词频饱和及作品级 IDF；不要将若干普通 BM25 得分相加冒充 BM25F。

先补开发集中已定位的作品，再按品类选未用于这些失败题的新作品、冻结新问题。旧题修复率与新题结果分开报告。首组只测词法字段策略，保留 MiniLM，不把补中文、换模型、加重排同时打包。

## 后续：模型、聚合与重排分别比较

1. **MiniLM vs multilingual-e5-base**：固定同一段落和候选数，仅替换 dense 编码器。E5 的 query / passage 前缀连中文也要加，向量为 768 维，不复用现有 384 维索引；重新建版本缓存并保持查询与文档使用同模型。[E5 官方说明](https://huggingface.co/intfloat/multilingual-e5-base)
2. **作品级聚合＋Weighted RRF**：每一路先将切块按 source_id 聚合，保留最佳证据片段、分数和命中数量；同一作品只贡献一次该路排名。词法 1.2、语义 1.0 仅作为实验初值，不能提前称最优。报告实际召回了多少不同作品，避免将 50 个切块误称为 50 件作品。
3. **Reranker**：仅在正确作品稳定进入 Top30 后实验。它不能恢复未进粗召回的作品，也不能取代编号分流。BGE-M3 编码器和 BGE Reranker 为不同角色，不把模型支持多种检索能力等同于本项目已经实现。[BGE-M3 官方说明](https://huggingface.co/BAAI/bge-m3)

每组分别记录 Exact Match Top1、中文名称／口语 Recall@5、MRR、模糊问题的作品去重与候选分布、P50/P95、构建时间和进程内存，并列出新修复与新退化。当前 44 题是开发集；不能只反复调这组题来声明上线质量。

图片保持独立评测。此前局部重排缺乏主体证据的结论仍成立，它是后续可再验证的实验分支，不是当前生产链路。
