# 照片身份与相似推荐的边界

本页保留 v6 阶段的策略及历史结果。后续已修复原花器的过度拒识、补充全貌参考和文字候选参考图；原花器不再强制展签，另一易混淆花器仍保留要求。当前版本及未解决案例见 [蓝白陶瓷诊断](blue-ceramics-diagnosis.md)。

2026-10-01。游客上传高度相似的库外作品时，最近邻和模型给出的候选都不能直接作为作品身份。本次沿用 DINOv2 图像召回、文字检索和 DeepSeek 核对，不增加训练或向量数据库。

## 产品行为

| 结果 | 展示 | 下一步 |
| --- | --- | --- |
| likely_match | 有具体特征支持的候选，仍提示确认 | 用户对照图片后确认；当前不自动进入讲解 |
| uncertain | 还需确认，最多三件候选 | 确认候选或补拍关键部位 |
| no_reliable_match | 当前图库暂未找到可靠匹配 | 可展示一件明确标记的相似作品；补拍展签或全貌 |

不显示百分比，不声称现实中馆内不存在该作品。图像分数只参与候选排序，不视为校准过的身份概率。`service_unavailable` 单独呈现，不能算拒识成功。

## 判定与已知易混淆藏品

核对输出包括具体部位的一致/差异、是否具有区分性以及下一步需要的照片。结构矛盾优先于整体相似；通用色彩、题材和轮廓不构成独特身份证据。同一部位重复描述不重复计数。参考图绑定候选 ID，文字候选没有参考图时不能单靠文字描述晋级。

真实复测证明，模型仍可能把相似花器的细节说成一致。**不能宣称提示词消除了误认。** 在参考图库配置 `identity_requires_label: true`，对已知易混淆的馆藏采用更严格规则：没有照片展签中的完整登记号支持时，只允许作为相似推荐。该规则作用于整件馆藏的所有查询图，不读取测试文件名、图片哈希或 Cleveland 名称，不把库外反例加入图库。

v6 阶段两件 Delft 金字塔形花器启用此规则；其他作品仍使用一般视觉证据规则。即使有登记号，明确的视觉矛盾仍阻止身份推荐，用户确认仍必需。OCR 也可能出错，本轮未验证真实展签的读取率；单元测试仅验证编号匹配边界。

**代价：正确的 V&A 花器照片没有展签时也可能只得到相似推荐。** 这是保守的产品策略，不是精细识别能力提高，也不是通用 OOD 检测器。

## 会话与 Trace

- `confirm`、`view_similar`、`retry` 分别记录。查看相似作品不能调用确认接口，也不计识别成功。
- 确认仅写入 `user_confirmed_object_id`，不是人工评测真值；机器的 `identity_confirmed` 仍为 false。
- 浏览相似作品后，讲解显示独立提示，后续问答带“照片身份未确认”的上下文约束，不能把馆藏年代/作者套给上传照片。
- 新照片清空当前作品身份与短期对话上下文。补拍用 `parent_photo_trace_id` 关联前次尝试；原 Trace 不覆盖。
- 操作只允许本会话已有候选，跨会话拒绝；连续重复点击同一操作不重复追加事件。
- Trace 保存分档原因、部位代码、排序、操作和版本；不新增保存原图、OCR 全文或自由文本图像描述。脱敏导出保留分档和动作，补拍关联 ID 匿名化。

## 本地真实回归结果

固定 22 条资料、15 张参考图，使用补库后的三张开发图；同一模型，不新增训练。v4/v5 是失败的中间尝试，记录保留。v6 更改了核对提示词及两件花器的判定策略，因此以下是开发回归，**不是单一算法的严格 A/B，也不是正式准确率**。

| 输入 | v4/v5 中间结果 | v6 最终结果 |
| --- | --- | --- |
| V&A C.615-1925 另一角度 | 新花器首位，仍混入另一花器 | 无可靠身份匹配；正确新花器为首位相似推荐，需展签 |
| V&A Samson 展厅图 | v4 输出结构校验失败；v5 正确候选 | 正确 Samson 身份候选，仍需用户确认 |
| Cleveland 2024.27 花器 | 错把新 V&A 花器列为 likely_match | 无可靠身份匹配；新 V&A 花器仅作为相似推荐 |

Cleveland 案例点击浏览后，追问“那我拍的这件是哪年的？”返回资料不足，没有将 V&A 年代赋给照片。结果来自真实模型与 MongoDB Trace，不是前端固定文案模拟识别。

原花器旧展厅图跌出图像前三的已知召回退化仍未修复，见 [补库评测](lookalike-evaluation.md)。新的局部图、不同角度、复制品以及库外相似图仍需要继续测试。不要以这三张已知开发图宣传泛化效果。

- 完整功能回退需回退本次代码提交并恢复旧图库路径，保留 MongoDB 历史记录。新字段均为附加字段，无破坏性迁移。
