## 冻结范围

- 使用原十二图包中的 01／04／05／08／11／12：花器完整图、海神完整图、花器顶部、海神背部、Cleveland 花器、阿波罗与达芙妮。

- 固定 1,012 件馆藏，每张照片只执行一次真实观察，再调用实际 `PhotoRecognizer` 的 DINOv2 与文字候选构建。文字 BGE 关闭，与底款实验一致，不能当作开启 BGE 的网页完整验收。
- 观察输出、候选及其顺序、参考图和 user 消息在两组之间相同，仅 system 协议与接收规则不同。没有向候选中注入正确答案。
- 新旧组交替先后顺序，各重复三次；6 次观察加 36 次核对，共 **42 次调用**，没有自动重试或补跑。
- 执行前冻结门槛：观察及比较完整、无错误身份候选、新版完整图六次均保留正确候选、馆内各题正确候选次数不低于旧版。新旧任一组执行失败也记录为本次严格对照未通过；新版三次错误候选独立足以否决启用。

## 失败分层

**召回层：**海神背面既未进入视觉前三，也未进入该观察描述的文字前五；因此五张核对参考图中没有正确海神。其余三张馆内图的正确作品均进入核对。本轮没有评到“正确海神参考图已存在时，新版能否识别背面”，不能将海神全部失败归给核对。

**核对层：**面对错误候选，新版仍有责任不误认。三次都将参孙作为候选。第一条原始证据把海神背部写成正面，并把人物上下关系和持物动作描述为独特匹配；规则收到两个 `same_region=true` 的正面匹配后放行。表面与区域字段是模型的自报信息，不是像素对应事实，新增字段无法保证这些声明正确。

**协议层：**花器顶部一次遗漏四个参考候选。该问题与海神的错误对应证据分开记录，不能通过放宽候选完整性校验来解决识别问题。

因此，[底款小实验](surface-verification.md)中盘背误否决消失，只支持那两个案例；扩大开发回归后出现了不可接受的错误候选，综合决定是不采用此版默认行为。

## 时延、用量与证据

18 次旧版比较的样本 P50/P95 为 6.256/21.179 秒，新版为 5.657/10.614 秒（最近秩，含有耗时记录的失败项）。不含共享的一次观察、检索或讲解，不是生产端到端延迟，也不能据此宣称新规则更快。

42 次请求获得 41 条 usage；已知总 Token 为 **142,550**。缺失调用的消耗未知，总量和费用均不填零。原图、OCR、参考图、完整模型回复、逐次预留及哈希保存在忽略目录 `eval/private/surface-controls-v1/`，未上传 GitHub。

后端 **561 项检查通过**，新增评测测试确保服务失败不会计为成功拒识、混有错误作品的候选仍算错误、缺失或重复实验行不能通过门槛、42 次请求上限不可越过。36 行比较结果中，34 份成功执行响应离线重放一致，2 行执行失败原样保留；重放新增调用 0 次。

评测批次 `surface-controls-v1-paired` 已通过管理 API 写入 MongoDB 并从面板读回，显示“不采用”。网站健康接口确认仍为 `legacy`。公开[脱敏摘要](surface-controls-results.json)与代码保留了这次失败，未修改先前底款实验分数。
