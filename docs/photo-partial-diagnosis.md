这是已知单件作品的小样本诊断，不计算通用准确率，不代表馆内实拍通过。两次相同结果也不构成稳定性保证。用户提供的是应用截图，而非当时上传的原始照片；截图整张重放会被模型视为界面，这一结果单列，不用于上述原图比较。

## 已定位的机制

当前链路是照片 → 视觉文字描述 → BM25／文本向量混合检索 → 照片与候选文字记录核对。页面上展示的作品图片没有作为参考图传入比对，也没有图像向量索引。

1. **视觉信息丢失**：局部图中的海螺被描述成“褶皱布料”，通用头部／手部描述无法保留关键区分特征。
2. **候选漏召回**：局部图两次都未把 `va-neptune-triton` 放入前5候选。最后的比较步骤无法选中根本不存在于候选列表的作品。
3. **确认阶段不是唯一瓶颈**：仅在隔离诊断里保持原观察输出、图片、比较提示词不变，并把已知正确作品加入原候选，模型返回了该作品候选。这是已知答案辅助的定位实验，不是改进算法，更不能算修复后的准确率。
4. **语料形式有影响的线索**：V&A 记录是英文讲解长文，图片观察主要输出中文。把不含作品名／作者名的英文外观短语用于独立检索时，可以召回该作品；这是线索，语言、长度及词汇同时变化，尚不能据此单独确定跨语言因素的贡献。
5. **整体图也不保证通过**：额外测的馆方展厅全景图与官方头部特写也漏召回；不能向用户承诺“只要拍全就一定能识别”。全景观察中出现大量展厅背景，属于待单变量验证的干扰因素。

## 可重放证据

所有原图、观察输出及完整模型记录仅在本地 Git 忽略目录。

- `data/private/va-photo-cases/article-provenance.json`：条目四张原始图来源、哈希与许可页面快照路径。
- `eval/private/va-partial-baseline.json`：馆方全景、馆方头部、两张用户应用截图及 AIC《睡莲》对照。后者正确匹配；不是相似雕塑负例。
- `eval/private/va-article-diagnosis.json`：四张原图、逐阶段输出、候选列表和仅补入正确候选的诊断。
- `eval/private/va-article-repeat.json`：局部及侧后方原图复测。
- `.runtime/probe_va_article.py`：固定输入与当前真实链路。首次输出 `BASELINE_MISSES ["article-1"]`，复测相同；报告已存在时拒绝覆盖。原有观察文字的检索重放各两次均漏掉正确作品，可在无需模型请求的检索阶段复现。

本轮没有获取原手机上传图，也没有修改生产日志以保存照片或OCR。当前后台管理令牌未启用，无法读取用户此前请求的原始运行记录；没有为诊断开启管理访问。

## 建议下一次最小改动

优先修复照片入口的候选召回：为作品维护独立、带来源的中英文外观与局部特征描述，并让视觉观察优先描述作品主体。艺术史讲解仍以官方底稿为依据，视觉猜测不得写回为馆方事实。随后再评估多角度参考图比对的必要性，避免直接堆模型。

验收继续使用这组冻结图片，同时新增未用于编写外观描述的角度与相似雕塑负例；必须检查误匹配，不能只提高命中率。证据不足仍提示补拍全貌或展签。手机拍屏的问题需用用户实际上传文件另做对照。
