# 原花器识别退化：诊断与蓝白陶瓷扩库

2026-10-01。用户反馈：此前能找到的、顶部带女性半身像的金字塔形花器，在加入相似藏品后无法识别。此次保留 DINOv2 特征检索与 DeepSeek 核对，不新增训练、向量数据库或其他模型。

## 复现与根因

用户提供的是清晰全貌图，对应 V&A O70710 / C.19 to J-1982。修复前的真实接口记录显示：正确作品进入图像第 2 位，但不能作为身份候选展示。另一个旧展厅测试图中，作品很小，图像排名为第 4 位；文字召回能找到它。

问题分成三层：

1. **图库覆盖不足。** 原花器只有一张中段细节参考图，不能支持核对头部、完整塔身和底座。此前下载的馆方全貌图没有加入索引。
2. **两路召回的衔接不完整。** 文字找到了图像前三之外的作品，但核对模型只收到图像前三的参考图。正确 ID 进入候选，并不等于模型看到了正确参考图。
3. **上一版规则过于保守。** 两件塔形花器都被配置为“必须有展签编号才可给出身份候选”，所以即使图像召回正确，也会被降为相似推荐。这不是 DINOv2 完全认不出该物体，而是参考资料和决策规则共同造成的拒识。

还发现可选的界面提示枚举偶尔不符合格式，导致完整识别请求失败。现在过滤未知的可选提示标签；作品 ID、身份判断和结构证据仍严格校验，不能将非法身份输出自动改成正确答案。

## 实际更改

- 加入原花器官方全貌参考 `2014HA4640`，保留原中段细节参考；藏品展示图也切换为全貌。
- 对文字召回但缺少图像参考的作品，最多补入两件真实参考图，优先全貌。图像前三加文字补充最多五件。补充路径不伪造图像分数。
- 原花器恢复通用的“具体部位核对 + 游客确认”策略；不是降低余弦阈值或自动确认身份。两处独特部位一致且无矛盾才可进入高支持候选；只有部分证据时仍提示不确定。
- 另一件易混淆花器 O77966 / C.615-1925 保留展签要求。它和 Cleveland 反例仍无法稳定依靠视觉区分，不能将保守拒识说成精细识别成功。
- 相似推荐先比较有效共性类别的数量，再用图像分数排序，避免仅有“轮廓相近”的雕塑压过具有蓝白、塔形、多插花口等共性的陶瓷。共性仍由模型判断，这不是可证明的身份分数。
- Trace 新增核对实际收到的参考作品、文字补入作品和规则版本；脱敏导出保留这些字段，不导出原图、OCR 全文或自由文本图像描述。

隔离内存环境先运行 13 张开发图及 4 张参考图连通检查，保留首次失败记录。期间 Samson 正面、人头局部各出现一次可选提示格式错误；过滤可选标签后分别重新调用成功。参考图连通检查不计识别准确率。

成功的含义是“正确作品可供游客确认”，不是机器确认照片身份。上述接口结果保存为 MongoDB Trace。

- 用户全貌图与新加入的 `2014HA4640` 是同一摄影画面，尺寸/编码不同。它只证明原始问题恢复，不能计作独立测试成功。
- `2014HA4641` 和 `2014HA4644` 未加入参考库，但与参考图来自相同馆方摄影环境，只作开发回归，不是盲测或真实游客评测。
- Cleveland 2024.27 未加入馆藏或参考索引；仅提供明确标注的相似作品，不给出库内身份候选。
- Neptune 的 `article-3` 局部图在修改前、修改后仍被拒识，并推荐 Samson 为相似作品。已保留该失败：模型精细部位核对仍不稳定，当前修复不解决所有局部图问题。
- 无线上 A/B、正式人工复核准确率或大规模泛化结论。后续应补充真实拍摄和未使用过的近似作品，分别统计召回、核对、规则拦截和服务错误。
