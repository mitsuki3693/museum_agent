# 会话任务流：修复与验收

本轮检查“找作品 → 确认作品 → 追问 → 换作品”能否完成。检索到资料、后台标为 `answered`、引用核对通过，都不单独代表游客完成任务。

本轮原始清单由用户提供，分为 10 个找作品、10 个讲解、8 个多轮交互、12 个证据与边界任务。原题已经用于定位问题，称为回归集。所有人工判分先留空，不由脚本补成通过。

## 本轮实现与验证

- `conversation-routing-v1` 在改写前区分编号、名称、明确查找、追问和比较。句中完整编号和裸编号共用已知字段索引；未知编号与扩展后缀不套用旧作品。
- 新查找解除旧选择，比较保留原选择。服务端返回当前选择，网页同步后不再重传旧作品 ID；候选仍需游客确认。
- 比较支持完整编号和明确长名称提取；两个明确名称均保留证据。直接点击另一件作品的预置讲解也清理旧作品历史，避免后续改写重新带回旧对象。
- 裸名称／仅名称查找保留同名记录；包含外观等额外条件的描述仍走原检索。普通追问中的“雕塑”“杯子”“找答案”等词不会单独触发换作品。
- 简单字段问题保留具体问题；材质采用版本化的整值中文词表。命中时附完整英文，未收录复合材料仍显示原文，不做部分替换或猜译。来源与逐字引文不改。
- 事实提取最多增加一次临时错误重试，限定网络／超时及指定临时 HTTP 状态，并受从请求开始计算的 45 秒阶段预算与原请求总预算限制。未知错误、鉴权失败、格式错误不自动重试。Trace 保存首次错误、重试及各阶段耗时，不保存供应商错误正文。
- 新 Trace 保存初始选中作品、请求作品及历史，作为私有复测依据；该数据不加入公开导出。

开发验证：634 项后端测试、26 项前端测试通过；其中前端新增的 6 项执行真实页面事件和请求。旧页面在同一套新增前端测试中为 3/6，新页面为 6/6。这是程序状态和交互回归，不是游客成功率。TypeScript 检查和前端构建通过。

本地实际网页已验证：句中的小写 `c.615-1925` 返回唯一正确候选及编号；`Table` 显示威尼斯装饰桌和巴黎写字桌两个可选择卡片。另有 5 条真实接口检查覆盖中文材质、编号切换、确认后的新材质、同名候选、未知编号澄清，均无模型调用；结果保存在私有 `live-deterministic-smoke.json`。

原题的 54 条输入还在实际馆藏目录上做了无模型路由检查：42 条带初始作品的输入中，40 条保持追问范围、T24/T28 的两次明确切换解除范围。该检查未执行完整候选确认流程，不证明生成答案正确。

证据核验规则没有放宽。旧花器准备讲解曾把 `whose arms…` 提取为 `the arms…`，逐字校验据此拒绝；不能把这个准备阶段错误直接算到 T22 正题。T37 的旧错误只有 `LLMError`，原因尚不确定；不能宣布已证明网络问题，也不能把另一次成功当作修复后的时延收益。

## 已保存的修复前证据

私有目录：`eval/private/task-flow-20261020/`。它受 Git 忽略规则保护，不随公开代码发布；内含原始问答和馆方资料，只用于本地复核。

- `baseline-traces.json`：2026-10-20 19:00–20:00 时段的 110 条文字请求 Trace，涵盖 17 个会话。保留失败、自动请求的讲解、追问和重试，不把 110 条请求当作 110 个任务。
- `baseline-attempts.csv`：按时间逐条列出原问题、有效作品范围、状态、耗时和 Trace ID，供关联任务。
- `session-trace-order.json`：同会话的 Trace 顺序。旧会话状态已经过期，历史消息只能由此前 Trace 重建；不能声称保存了原始完整请求上下文。
- `tasks-v1.json`：用户原始 40 个任务及步骤。题号、目标和必要步骤以这份清单为准。
- `task-mapping.proposed.json`：原题各步骤与历史 Trace 的文字匹配线索，仍须核对会话和首次／重试角色。仅标准化标点、空格和大小写，未用语义相似度自动认定同题。准备作品时触发的讲解失败记在准备阶段，不能擅自替代该任务的实际提问。
- `regression-40-scoring.csv`：40 个任务的人工评分表。首次结果与恢复结果分列；缺记录保留“待核对”。
- `supplemental-12.draft.json`、`supplemental-12-scoring.csv`：从当前真实语料另拟的 12 个补充任务，涵盖编号、名称、中文描述、追问、风格、切换、比较、歧义和证据不足。均为 Agent 拟题、未运行、未人工复核，不能当独立盲测。
- `manifest.json`：基线提交、语料哈希、模型和提示词版本，以及导出文件哈希。
- `复测执行单.txt`：便于边看边操作的 40 题清单；题目复制给系统，验收要点只用于人工评分。

修复前代码基线为 `f40d0a0`。Trace 中记录的模型、提示词和语料哈希用于核对运行版本。该导出不包含 API 密钥、登录凭据、上传照片，也没有调用付费模型。

## 先测这 8 项

按用户优先级，先完成 T14、T23、T24、T31、T33、T39，再补 T25、T26。具体原问题和必要步骤见本地 `tasks-v1.json`；不要为了通过临时改问法。

| 任务 | 主要检查 |
| --- | --- |
| T14 | 先确认原题要求的花器编号，再讲结构与插花用途；不能混入另一件同名花器的开口数量 |
| T23 | 多轮追问保持正确作品，分别回答问题涉及的事实关系 |
| T24 | 明确换作品后解除旧对象限制；确认新候选后，界面和后续回答同步切换 |
| T31 | 装饰风格不能直接推出制作国家；有依据可纠正的内容不应整题拒答 |
| T33 | 原文尚未确定的城市应保留不确定性，不能擅自确定 |
| T39 | 阅读正文中的制作地和部分组装地点，不能因结构化地点字段为空而拒答 |
| T25 | 宽泛名称先给多个有依据的候选，或提出能帮助区分的问题 |
| T26 | 中文材质说明可理解；英文原文和引用仍可查看；不能被外观颜色误导 |

这 8 项之后，补测 T28 的口语纠正换作品，以及补充题 S09 的“比较而不切换”反例。T24 和 T28 应分别覆盖编号切换、无编号的自然语言切换；不能只修通其中一种。

当前历史证据还存在两处限制：T14 的正文请求实际沿用了另一件同名花器，不能仅凭 `answered` 判通过；T28 的首轮指定说法及最后木材追问没有找到原样请求，不能把缺失步骤自动记为成功。评分表已经分别标记上下文不一致和记录缺失。

每项操作：

1. 新建对话，按清单执行初始选中作品和必要前序步骤。多轮任务中途不新建对话。
2. 原样提交第一遍问题。候选确认、预先设计的澄清是任务步骤；额外改问法和重复发送是恢复操作。
3. 记录首次结果、页面实际选中作品、Trace ID、耗时。失败也保留，不覆盖。
4. 如果重试，另记重试 Trace 和恢复耗时。不要用恢复成功改写首次失败。
5. 展开来源，判断事实、引用和表达是否满足要求。不能只看“核对通过”标签。

可直接填写评分 CSV；也可以按下面格式回复：

```text
任务：
首次：通过 / 失败 / 待核对
Trace ID / 时间：
初始作品、前序步骤：
实际回答或界面表现：
引用是否支持、中文是否可理解：
有没有额外改问法或重试：
恢复后的 Trace ID、结果：
```

## 如何完成 40 题的版本对照

先确认原始任务与已有 Trace 的对应关系。找不到第一遍记录、初始状态不明确或必要步骤缺失时，标“待核对”，不推定通过，也不推定算法失败。

在代码回归通过后，冻结新版本提交、语料文件、搜索字段、提示词、模型名、推理参数和会话准备步骤，再执行同一份清单。当前历史记录的会话状态不完整，因此它可以作为修复前观察，不能自动视为严格受控实验。若需要严格的版本对照，应让两个版本分别从同样的显式状态重放；避免在同一会话中先测旧版再测新版。

模型调用有波动时，预先指定需要重复的任务和重复次数，两版都保留全部结果，不能只挑最好的一次。网络异常、核验失败、知识缺口、选错作品分别归因。

新版本结果另存文件，不覆盖基线。测试过程中若继续改提示词、规则或语料，应记录新的版本号，并对受影响任务重新对照；不能将多个不同版本的最佳结果合成一个成绩。

现有 `museum_eval freeze` 针对旧的 20/8/4/4/4 题型配额。不要把本轮 10/10/8/12 的任务清单伪装成旧格式，也不要直接拿旧 `eval/questions.json` 代替这轮原题。

## 人工评分口径

| 维度 | 判定 |
| --- | --- |
| 首次任务成功 | 完成原题全部必要步骤，无额外改问法或重新尝试；预设澄清和确认可计入 |
| 定位／切换 | 正确候选能被用户选中；选中后界面和追问基于同一对象 |
| 事实 | 关键事实正确、没有新增无依据事实；“部分正确”另记 |
| 引用 | 引用直接支持相应陈述，且属于正确作品和版本 |
| 可理解性／风格 | 中文说明清楚，儿童／深入要求真正满足 |
| 证据不足 | 没资料时诚实说明；有资料被错误拒绝单列“过度拒答” |
| 服务与时间 | 调用异常单列；完整任务耗时包含内部重试和准备过程中阻断性失败 |

`有帮助`、`没有解答`是问题线索，不能直接充当事实金标准。只有 `待核对 / 未测` 的任务不计为成功或失败；报告时同时给出成功数、已判定数、计划任务数及待核对数。正式主指标要求相应类别全部任务完成复核后再给出 `成功数 / 该类任务数`。

12 个补充任务单独报告，不并入原 40 题分母。它们虽换了部分作品和表达，但已经由 Agent 阅读语料并拟题，不能称为独立盲测或代表全部千件馆藏的泛化准确率。

## 可以形成的结果

完成后报告“相同条件下，这类任务由 a/n 到 b/n”，并附修复的失败类型、仍未解决的问题、额外等待和错误回答是否增加。称为离线版本对照，不称线上 A/B。自动化通过只证明规则和状态切换；模型讲解质量与实际游客体验仍需人工判定。

## T14 补测：确认候选后重复消歧

用户实测发现点击马尔伯勒纹章款花器后，页面反复显示两件同名作品。后台记录确认点选 ID 正确；原因是所选作品没有有效预编讲解，`narrate` 回退到普通问答后，把按钮生成的讲解请求重新当成名称查找，清除了已选对象。

修复让明确的讲解动作保留已验证的作品 ID，按 ID 读取当前有效资料；不再运行名称消歧或问题改写。预编讲解缺失／过期时仍走原生成与核验流程，照片“仅相似”身份边界仍保留。普通用户主动找新作品、切换、比较继续使用会话路由。

新增真实 HTTP 调用路径的回归：先搜索同名作品，再分别确认两个候选，最后追问用途；覆盖预编讲解缺失和过期两种情形。修复前两项均因重复 `needs_confirmation` 失败，修复后通过。该测试不使用付费模型，只证明确认状态与资料范围正确；T14 的插花结构、用途和六个开口等内容仍需人工复测。

补测后完整后端回归为 636 项通过。另用当前实际语料、禁用模型的本地副本检查两件花器：确认各自 ID 后，讲解与 T14 用途追问均只使用所选作品；马尔伯勒纹章款进入资料回退，另一件使用预置讲解，均未再次要求消歧。私有结果为 `t14-confirmation-hotfix-local.json`，不代表实时生成讲解已验收。

## 可选改写的独立等待预算

七项历史对照中，T31 虽然回答正确，但请求耗时从 7.597 秒增加到 26.369 秒。后一次 Trace 的查询改写阶段发生网络错误，单阶段耗时 21.192 秒；随后使用原问题成功完成回答。这里没有证据将网络错误归因于 VPN，也不是整体模型准确率退化。

修复只改变可选查询改写：`MUSEUM_REWRITE_TIMEOUT=3` 为独立等待预算，超过预算取消本地异步调用，使用原问题继续检索，不重试改写。当前作品、历史消息、照片身份限制和生成后的证据核验保持不变。调用方取消整项请求时继续传播取消，不在后台继续生成。客户端取消不保证服务商没有处理或计费。

健康接口返回 `rewrite_timeout_seconds`；Trace 的 `rewrite_policy` 保存策略版本、预算和回退方式，`timing.events` 保留超时或网络错误。没有返回的 Token 用量不估算为零。3 秒只限制改写等待，不保证完整问答 3 秒完成；生成、事实提取与核验仍有独立的失败可能。

新增测试在真实问答引擎中模拟慢改写，旧代码未按预算取消而失败。覆盖慢调用取消、快速改写正常使用、网络错误回退、无效改写回退、核验拒绝仍拒绝，以及整项请求取消。均使用假模型，不产生 API 费用，也不证明真实模型回答质量或线上 P95 改善。可通过环境变量调整预算（大于 0 且不超过 25 秒）；历史评测与旧版快照不回填。

本次完整后端回归：645 项通过，包含 9 项新增预算／取消／核验保护场景。前端未改动。历史 T31 耗时仍保留 26.369 秒，不用模拟测试结果替换该记录。
