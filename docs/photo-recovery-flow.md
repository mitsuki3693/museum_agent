# 照片确认与一次补拍后的退出路径

2026-10-07。此轮完善游客任务流程，不更换识别模型，不扩大当前图库，也不声明准确率提高。

## 行为

- 判定规则返回最多两件可确认候选；顺序仍取现有视觉排序。全部比较记录保留在 Trace，截断展示不等于提高召回率。
- 候选展示图片、名称及已有的外观提示。提示不是模型编造的区别说明；当前没有可靠的两件作品差异摘要。
- 用户选择“就是这件”后才进入所选作品讲解。`user_confirmed_object_id` 是用户声明，`identity_confirmed` 仍为 false，不能计作自动识别正确。
- 无可靠身份时维持相似作品入口；“了解这件相似馆藏”记录为 `view_similar`，不允许伪造为 `confirm`。不为了凑满两件而增加相似作品。
- “都不是”记录 `reject`，禁用该条候选确认，保留补拍和其他入口。
- 初次结果可以补拍全貌或展签。通过 `parent_trace_id` 关联同件作品的一次补拍，服务端返回并保存 `retake_count`。
- 补拍完成后仍不确定，停止继续建议补拍，改为“输入名称或展签文字”或“浏览馆藏”。前者清理作品上下文并聚焦输入框，后者打开馆藏选择器并聚焦搜索。选择其他作品可开始新任务，不是永久限制相机。
- `service_unavailable` 不作为图像不匹配，隐藏身份和相似卡片，允许稍后重新发送；该失败结果不会额外消耗补拍次数。HTTP 请求失败也有文字查找和馆藏入口，不自动重试。
- 确认、相似浏览、拒绝、补拍、文字查找、浏览馆藏均经过会话校验。新动作与补拍次数进入原有 MongoDB Trace 和脱敏指标导出；没有新增保存游客原图。

一次补拍是任务引导上限，不是全局请求配额：用户可取消补拍、开始新任务；同一父记录的并行分支也不能当作独立用户样本。统计时应按会话与父子链去重。

## 为 300 / 1000 件扩库准备独立测试

`scripts/prepare_photo_holdout.py` 已生成本地采集计划：40 件有参考图的 V&A 作品，排除旧 12 图包使用过的作品 ID；按馆藏标题轮流选取，尽量覆盖类别，但不代表随机抽样或全馆比例。

计划共 150 个**空槽位**：120 个库内照片名额（每件清晰全貌、局部、其他角度或拍屏各一）及 30 个库外相似作品名额。按作品隔离为 110 个开发槽位、40 个保留测试槽位。同一件作品的全部照片在同一分组；库外同件照片也须人工按作品归组，不能跨组。当前实际收集 0、人工复核 0，`ready_for_evaluation=false`。

本地计划位于 `eval/private/photo-scale-v1.collection-plan.json`，不会提交图片、馆方文本或逐件清单。`target_source_id` 仅为采集目标，不是已核验金标准；`gold_source_ids` 均为空。该文件不是可直接喂给评测程序的冻结题集。

接下来依次完成：

1. 收集独立来源照片，记录作者、许可、来源 URL 和原始图片 ID。不能拿参考原图裁剪或拍屏后当成独立泛化样本；同源拍屏只作鲁棒性检查，单独报告。
2. 检查原始与标准化图片哈希，人工核对裁剪、压缩、镜像和近重复；计划中已列出图库排除来源与哈希。样本不足的作品如需替换，须记录原因并在模型测试前固定，不能按表现挑图。
3. 人工核对具体作品身份及库外标注，记录复核人和时间。无法分清具体作品的图保留为歧义案例，不能强填身份。
4. 冻结数据、参考库与模型版本。保留测试集不用于调参，先在开发集比较局部匹配；改阈值后不能把已看过的保留结果当盲测。
5. 扩到 300、1000 件时只换图库，报告候选排名退化、错误身份、用户确认后的任务完成及各类耗时。扩库后重新核验库外样本是否仍在库外。

界面兜底已实现；150 张独立图片收集、LightGlue 对照和扩到 1000 件都尚未完成。
