# 表面对应核对：盘背与正面不再作为矛盾

2026-10-10。实现 `surface-correspondence-v1` 实验协议，完成两张底款照片各三次真实核对。盘底目标原先三次均被否决，新协议三次均判为不可比较。**网站默认仍为 legacy；未完成完整图和库外近似物回归，不宣称整体识别率提高。**

## 实现与原因

原协议只给出部位和差异，无法表达“装饰是在盘背还是盘正面”。本轮为每条证据增加 `query_surface / reference_surface / same_region`，同时保留两侧可见性、实际细节与 `visible_match / visible_conflict / not_visible / cannot_compare`。

- 正面、背面、底面、顶面、侧面、未知为有限枚举。两个面明确一致、区域对应、两侧可见且有描述，才允许匹配或冲突进入身份规则。
- 不同面、未知面或不同区域上的差异变为不可比较；该规则也限制正向匹配，不能只去掉负向证据而保留虚假的正向证据。
- 模型声称 `different_work` 却没有有效冲突，降为不确定；声称 `same_work` 却没有两个独特部位支持，也降为不确定。无冲突本身不产生身份候选。
- 完整 OCR 编号继续提供独立浏览入口，不替代视觉证据。近似物的展签保护、游客确认、会话隔离保持原逻辑。
- 同面同区域的有效冲突保留。模型遗漏面信息或漏评/重复/添加候选时失败关闭，不自动修补字段或追加调用。
- Trace 仅记录有限枚举、布尔值与候选 ID，不记录图像、OCR 原文或模型的自由文本细节。

面与区域对应仍是模型的判断，并非经过人工核实的空间定位。把错误的面标成相同面仍可能产生误判；本功能不等于解决三维视角识别。

## 验收与默认状态

后端 **557 项测试通过**。新增测试经实际 `PhotoRecognizer` 路径验证不同面、未知面、不同区域、同面匹配、真实冲突、缺失字段和展签保护；另验证缺乏证据的全局身份结论、候选集合完整性与默认配置。合成测试只能验证规则，不能代替真实库外误认率。

固定响应再次回放通过，新增调用 0 次。评测批次 `surface-correspondence-v1-two-bottoms` 经管理 API 写入 MongoDB，并从评测面板读回，状态为“待验证”。底款图、参考图、原始 OCR、模型响应全部保留在忽略目录，GitHub 只保留代码、合成测试和脱敏报告。

开关为 `MUSEUM_PHOTO_VERIFICATION=surface`，只供受控实验；默认 `legacy` 未修改，现有编号浏览功能继续可用。本轮没有修改前端，不需要新的视觉验收。实验脚本 `scripts/evaluate_surface_verification.py` 提供 `prepare / live / replay`；已有 live 批次不可重复运行，公开克隆没有私有数据，无法直接复现数值。
