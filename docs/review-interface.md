# 回答与识别复盘界面

## 任务与信息顺序

页面沿用 MUSE. 既有界面方向；首屏先交代复盘用途，再提供管理凭据、数据保存与备份状态、筛选条件和最新记录。自动分类只提供线索，事实和原因由维护者确认。

| 步骤 | 当前行为 |
| --- | --- |
| 1. 载入记录 | 输入独立管理凭据后载入。凭据只保存在当前页面状态，刷新清除；不写入浏览器持久存储。 |
| 2. 检查保存状态 | 显示 MongoDB 或内存模式、每日备份开关、最近结果及完成时间。MongoDB 模式允许立即备份；每日备份仅在服务运行时执行。 |
| 3. 筛选 | 按资料检索、图片识别、回答生成、依据核对、服务故障等失败环节，以及执行结果和会话编号筛选。提交筛选后回到最新范围。 |
| 4. 逐条查看 | 对话与照片识别记录合并，按创建时间从新到旧排列，显示类型、时间、执行结果、编号、耗时与关联反馈。候选、引用、生成过程及版本默认折叠。 |
| 5. 人工复盘 | 分别填写处理状态、问题发生环节、原因／改动／判断依据，以及可选的回归记录编号。备注最多 1000 字；保存成功显示“已保存”并重新载入记录。 |
| 6. 导出指标 | 按当前筛选和时间范围导出白名单字段，每批最多 500 条。导出不含问题、回答、引用原文、备注和照片，记录与会话编号重新加盐哈希。 |
| 7. 查看评测批次 | 独立展示批次执行状态、题集是否复核、回答人工评分完成数量及摘要。未完成人工复核的批次仅用于工程检查。 |

人工复盘状态为“待复盘”“已确认问题”“已修复待跟踪”“符合预期”。这些是维护记录，不能自动证明改动有效；关联回归记录提供后续核查入口，仍需检查同条件下的实际结果。

“查看更早记录”沿时间游标继续查看，“回到最新”返回首批。无匹配结果时提示清除筛选，或先完成一次游客问答／识图。请求期间操作按钮禁用，失败以错误提示反馈，备份和导出完成使用状态提示。

## 视觉与交互依据

实现依据为 `web/src/app/review/page.tsx`、`review.module.css` 和 `web/src/app/globals.css`。保留黑紫背景、深紫输入表面、白色 MUSE. 衬线字标、浅紫操作按钮及暖黄色反馈／焦点提示；不复制馆方标志。

主体为最大宽度 1080px 的单列记录流，以分隔线组织凭据、运行状态、筛选、记录和评测区域。字号层级服务于扫描：页面标题最大 38px，记录标题 19px，回答正文 15px，表单与操作 14px，记录元信息 12–13px。详细过程折叠呈现，展开后长内容可换行并在限定高度内滚动。

输入与按钮最小高度为 44px；焦点提供可见轮廓。650px 以下，筛选改为两列，会话条件和提交按钮占满一行，人工复盘字段改为单列，运行状态和列表工具上下排列。这些是现有样式行为，不能替代移动设备上的可读性与操作验收。

## 数据与证据边界

- 复盘页可查看受凭据保护的原始问题、回答和过程记录；“导出脱敏指标”采用另一套字段白名单，不等于导出匿名原始语料。
- 照片运行记录保留图片哈希、候选、失败步骤和耗时等信息，不存储或导出游客上传原图、文件名、EXIF 或 OCR 原文。
- 备份包含对话原文，必须留在本机私有目录；备份与脱敏导出不是同一种产物。保留与删除限制见 [持久化说明](persistence.md)。
- 开发者手工提交的反馈须保留其开发检查含义，不当作真实游客研究。题集复核、回答人工评分、人工问题复盘也不能互相替代。
- 本轮记录了真实服务失败；记录完整、页面可操作不意味着回答或识图成功，更不构成准确率结论。
