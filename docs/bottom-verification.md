# 底款核对：正反面误判与编号线索兜底

2026-10-10。已复现盘底照片的失败原因，并上线一个受限的产品兜底：完整编号命中但图像核对未确认时，允许查看编号关联馆藏。**没有将该结果升级为视觉身份确认，也没有解决通用的正反面对应问题。**

## 真实证据

沿用上轮两张底款照片及第一次真实 OCR 输出，固定 1,012 件语料、DINOv2 视觉索引和每组实际选出的五张候选参考图。文字检索关闭 BGE，与上轮隔离实验一致。执行原生产核对提示词，每组重复三次，共六次 DeepSeek 调用，不重试、不重跑 OCR。

离线捕获真实 `PhotoRecognizer` 链路确认：两件目标及各自参考图都进入核对，均由文字召回补入。因此这轮失败不在目标被检索截掉这一环。

| 两个已知开发案例 | 原版正确作品可展示 | 原版模型核对 | 新规则回放后的入口 |
| --- | --- | --- | --- |
| 壶底 `va-2020MP1936` | 3/3 | 两次 likely、一次 uncertain，均需游客确认 | 保持原候选展示；组件编号不强行精确匹配 |
| 盘底 `va-2007BM5078` | 0/3 | 三次 different_work；完整编号均支持目标 | 3/3 可按编号浏览，仍不是视觉候选或身份确认 |

模型将盘背的编号、日期字样与盘正面的人物花卉装饰对比，又将两面的边饰视为矛盾。现有参考图确为正面，游客输入为底面；这是比较了不同面的证据。原协议只记录 `part` 与 `relation`，没有可核验的两图表面对应信息，不能靠关键词猜测或直接删掉冲突来“修复”。

壶底虽然三次都展示目标，其中两次将整体轮廓作为独特匹配；本轮未证明这些正向视觉证据可靠，不能把展示率写成真实识别准确率。

## 本轮实现

- 新增独立 `number_candidates`，只接受现有完整 OCR 字段路由产生、已校验来源的作品 ID。模糊号码、描述中的猜测、未知 ID、组件编号不走此入口；最多显示两件，保留同号歧义。
- 视觉冲突、原候选等级、相似推荐及身份状态不被改写。服务失败不展示遗留的编号线索；已作为正常候选展示的同一作品不重复出现。
- 前端明确显示“编号有线索，照片尚未确认”，展示真实馆藏图片，按钮为“查看这件馆藏”；引导补拍正面或展签。
- `view_number` 是独立的浏览操作。只能选择当前会话该条 Trace 的编号候选，不能通过 `confirm` 将它伪造成识别成功；不写入 `user_confirmed_object_id`，`identity_confirmed` 仍为 false。
- 浏览后的讲解保留“按编号查看，不代表确认照片”的提示；后续问答传入身份边界，避免将所选馆藏的作者／年代直接套到上传照片上。Trace 和脱敏导出只增加候选 ID、操作码与版本，不保存原图或 OCR 原文。

这解决“已有完整编号线索却无从查看目标”的流程中断。它不靠调低阈值，不声称原先的视觉否决已被算法证明错误，也不允许在疑似款或库外作品上直接宣布身份。

## 验收

- 原始六次模型响应保持不变，只回放本地展示规则，新增模型调用 **0 次**。壶候选 3/3 保持；盘子作为独立编号线索从不可浏览变为 3/3 可浏览。六条视觉决策逐条相同。
- 后端 **542 项**通过，含新增九项编号浏览与后续身份边界检查；前端 **15 项**通过，生产构建通过。新增接口集成测试验证跨会话拒绝、非法作品拒绝、重复点击去重、不能伪造确认、后续上下文提醒。
- 本机网页在 1440px 和 390px 两个视口完成回放验收：使用保存的真实核对响应、真实候选图片、实际 `photo-actions` API 和 MongoDB；讲解响应为本地回放，没有额外付费调用。两端无横向溢出或页面 JS 错误，点击记录落库且身份仍未确认。开发测试会话和 Trace 在读回验证后定向清理。
- 该浏览器检查不是 iPhone/Safari 实测，不是重新上传后的完整模型验收，也未覆盖新的库外图片。题集仍是两张已知开发图，没有人工盲评，不报告全库准确率或线上 A/B 提升。

本轮六次核对的用量与单次耗时见[脱敏结果](bottom-verification-results.json)。费用保持未知，不用未核实单价估算；前一轮 OCR 的六次调用单独保存在原批次，不合并为本次核对成绩。

## 归档与复现

评测批次 `bottom-verification-v1-number-clue` 已通过实际管理接口保存并从 MongoDB 和评测面板读回。“采用”仅指编号浏览兜底，不能解读为采用了新视觉算法。

本地证据位于 `eval/private/bottom-verification-v1/`：原始捕获消息（含参考图）、计划哈希、逐次调用预留及响应、固定响应回放、测试记录、归档回执。全部被忽略，不上传 GitHub。只公开实现、合成测试和脱敏指标。

脚本 `scripts/evaluate_bottom_verification.py` 提供 `capture / live / replay`；当前批次已完成，禁止重复执行 live 或覆盖证据。`replay` 不发送图片，只对已有响应执行当前规则。公开克隆没有私有照片与模型缓存，不能直接复现这些数值。
