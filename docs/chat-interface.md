# 游客聊天入口：2026-09-29

## 本轮问题

原页面把拍照、馆藏列表、讲解模式和对话分成多个区域；第一次回答后拍照区消失，游客继续看下一件作品时缺少入口。用户希望像聊天助手一样，随时拍照、提问和追问。

## 当前实现

- 单一对话流：上传照片、候选作品图片、确认、讲解和追问依次留在同一段对话中。
- 常驻输入区：文字、拍照、相册、语音都在底部；支持先选照片，再附带一个问题。发送前仍可移除照片。
- 照片有问题时，先识别并请求确认，再携带确认后的作品 ID 回答原问题。仅发照片或直接选示例作品时，先提供简明讲解。
- 回答下方提供深入／儿童等其他讲法；避免全局模式开关与当前回答脱节。播放仍使用设备的浏览器语音能力。
- 名称查找移到顶部的折叠菜单；简短示例作为次要入口。引用依据、完整原文与来源默认折叠，仍可核验。
- 图片识别失败可重新上传；问答传输失败可重试原消息，复用同一请求编号，避免把一次重试记录成两次提问。
- 新对话释放本地照片预览并清空界面上下文；旧会话已失效时也能重新开始。后端原有会话保留与删除机制不变。

## 验证方式与边界

生产构建与 TypeScript 检查通过。前端网络模块的 3 项回归覆盖 HTTP 局域网缺少原生 UUID、正常 UUID、失败后以相同请求编号重试。检查运行实际请求构建代码。

浏览器通过本机真实后端验证了简明／深入／儿童讲解，以及局部照片附带问题 → 候选图片 → 确认 → 回答原问题。确认作品后仍可从底部选择下一张照片；引用可展开，明确反馈显示“已记录”。另已核对中文名称筛选、新对话清空界面，以及“很多睡莲的画”返回《睡莲》候选图片。使用既有本地开发照片，未增加公开素材。

这些属于开发冒烟验证，不是正式准确率、线上 A/B、专家评分或 iPhone 实机认证。V&A 原稿、截图与照片仍在本地忽略目录。手机摄像头、软键盘、语音权限和音色仍需要用户实机体验。

## 收尾与后续顺序

1. 核对聊天入口和关键游客流程；保留已知局部识别失败及拒答案例。完成用户对讲解的体验评审后，再汇总为验收结论。
2. 路线规划：先选择一个博物馆，确认楼层图、展厅连接关系、作品所在位置与来源时效；首版围绕参观时间和兴趣推荐参观顺序。有示意数据时须标明模拟，不能当成实时室内导航。
3. 工作人员端：先接讲解内容维护与游客反馈复盘，再讨论环境风险工具。无需等游客端拥有所有可能功能才开始。
