# 分层评测面板：第一轮迭代交付

2026-10-10。入口为 `/review#evaluations`，使用现有本机管理凭据。此功能把 MongoDB 中的评测证据变成可读、可筛选的面板，不重新运行模型、不改变算法、不修改历史分数。

## 已完成的功能

- 在既有复盘页增加“运行复盘／分层评测”切换，保留历史记录、反馈、人工复盘、备份和原始摘要入口。
- 提供文字检索、讲解与问答、局部识图、路线规划、文保问答五层，加上独立的工程可靠性层。支持按层和题集复核状态筛选。
- 每个批次独立展示执行状态、题集复核状态、逐条人工评分数量、采用决定、指标分母，以及题集／语料／模型／提示词／视觉索引版本。
- 已适配配对文字排名、两轮局部裁剪实验、单次问答耗时与人工事实／引用评分。未适配的旧批次保留“尚无已适配的结构化指标”，可回运行复盘查看原始摘要。
- 新批次可提交可校验的 `display` 元数据，明确所属层、适用范围、采用决定和指标。比例超出 0–1、分母为零、数值与分子分母矛盾、NaN 等会被拒绝。
- 新增只读管理接口 `GET /api/museum/admin/evaluations`。复用既有管理鉴权，不返回逐题原始内容、照片或候选明细；这不是新的多角色账号系统。

## 指标的边界

1. 执行完成只表示批次跑完，不能自动变成“方案采用”或“质量通过”。两轮已拒绝的裁剪实验会明确显示“不采用该实验方案”。采用决定也不代表此刻已部署。
2. 题集是否复核和回答是否逐条评分分开显示。缺失人工评分不补零，不从模型输出推断人工正确率；零事实／引用分母显示“未测／未评分”。
3. 不同题集、语料、模型和分片不自动合并。同一实验拆成 80/27 条归档时，分别显示对应分片；不会将重复的整批摘要累计两次。
4. 图片实验的 Top5 是正确作品进入候选的比例；库外图不混进库内命中率分母，也不把候选召回当成身份确认成功率。
5. 单次问答耗时明确标注样本数 1，不自动推算 P95。新实验可带已计算、说明范围的延迟指标，但必须有其本身的测量记录。
6. 面板最多读取最近 200 批，明确显示“已载入／总批次”；缺口统计只覆盖这个窗口，不宣称历史数据不存在。

## 本机实际验收

真实 MongoDB 共 19 批：文字检索 9、讲解与问答 1、局部识图 9。路线、文保和工程可靠性尚无归档到本集合的固定评测批次；已有文档或测试不被自动迁入、评分。

| 检查 | 结果 |
| --- | --- |
| 后端回归 | 519 项通过，包括新增 10 项指标、历史兼容和鉴权检查 |
| 前端检查 | 13 项通过，包括新增 3 项边界展示检查；生产构建通过 |
| 真实接口 | 19 批从 MongoDB 读取；未提供凭据返回 403；新面板不含逐题原始内容 |
| 真实交互 | 分类／复核筛选、未建路线评测的空状态、返回运行复盘、错误凭据清除已载入数据通过 |
| 已拒绝实验 | 主体裁剪三个方案各显示库内 Top5 14/20，采用决定为“不采用”，人工评分为 0/42 |
| 显示 | 1440px 桌面和 390px 移动宽度截图已检查；无页面横向溢出，宽表格在自身容器内滚动；无页面 JS 错误 |
| 付费调用 | 本轮 0 次；只是查询已存结果 |

移动检查使用桌面 Chromium 的 390px 视口，并非真实 iPhone/Safari 验收。截图位于忽略目录 `.impeccable/review/`，真实页面检查结果在 `.runtime/evaluation-panel-browser.json`；公开仓库只保留代码、文档与合成测试。
