# 游客描述找作品、图片确认与递进讲解

2026-09-29。由用户iPhone截图中的“很多睡莲的画”触发本次修正。

## 问题与修改

1. **图片空白**：原AIC外链返回403，前端隐藏失败图片，只留下“馆藏示例”。改为本项目静态提供三件已核对版本及许可的公有领域复制图，确认卡采用contain完整展示。来源、下载地址和SHA-256在`data/image-provenance.json`；图片位于`web/public/collection/`。未给其余九件虚构图片，暂无图的候选明确提示并提供馆方链接。
2. **找作品被当作知识问答**：原句的检索第一名已是`artic-16568`，因此不是“没搜到”。生成器却回答睡莲系列数量，审查器又把相当于25年的表达等判为新增事实。原失败完整保留`eval/colloquial-description-before.json`，不把模型审查意见都视为事实正确。
3. **先确认再讲解**：尚未选定作品时，区分画面描述与明确知识提问；描述返回经候选白名单校验的最多三件作品，前端显示图片、名称及确认按钮。未经用户确认不锁定作品、不生成历史讲解。找不到候选时请游客补充线索。历史中已有候选但尚未确认时，也支持补充描述；图像识别共用同一候选卡。
4. **递进而非预选深度**：移除顶部简明／深入切换；选择作品先简明讲解，回答后提供“再讲一点”“给孩子讲”。前者显式发送deep；普通问题默认brief。“给孩子讲”是基于现有资料的问答改写，尚未接入已批准的人工讲解库。
5. **错误说明**：事实核对失败改为说明“已找到相关资料，但讲解未通过核对”，不再用“换个问法”把内部失败归给游客。没有放宽事实检查，也没有把确认候选标为回答已核对。

## 验证边界

- 原句真实调用复现verification_failed，修正后真实调用得到needs_confirmation及唯一候选artic-16568。记录`eval/colloquial-description-after.json`。这是已知开发案例，不能用于宣称全体问题提升。
- 新增四项行为测试：描述先给候选、候选不能越过已检索ID白名单、明确知识问题仍须事实核对、拒绝候选后可在同一会话补充描述。最终全套后端85项通过。原有前端HTTP请求编号两项回归通过，Next.js生产构建通过。
- 三张公开作品数字图片均通过现有真实视觉模型链路，返回对应候选，结果在`eval/artwork-image-smoke.json`。输入及哈希在调用前固定，没有覆盖旧合成展签的失败记录。没有反光、遮挡、库外近似作品对照，不能当作手机拍屏或馆内识别准确率。
- 现有视觉链路仍是“视觉描述／展签文字→文本与向量检索→照片对候选文字记录核对”，不是新增以图搜图索引或针对博物馆训练过的识别模型。
- 局域网浏览器已实际输入原句并显示睡莲图片确认卡；确认后真实模型返回两条通过核对的简短讲解，并显示“再讲一点”“给孩子讲”。本轮尚未人工验证两个后续按钮各自生成的讲解质量。iPhone刷新新版本后的确认仍由用户完成。
