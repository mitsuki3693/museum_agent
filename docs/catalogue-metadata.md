# 千件库作者与年代字段检索

日期：2026-10-09。接续[中文词表修复](catalogue-glossary.md)，保持同一份 1,000 条 V&A + 12 条 AIC 语料、中文辅助字段、MiniLM、BM25F/RRF、BGE 参数和视觉索引。

## 修复原因与范围

“Find works by Giovanni Bologna”和“Find works dated 1930”原来都会受到正文提及的人名、年份及语义相似作品干扰，目标未进入前五。完整作者与编目标注年代属于明确条件，不能让正文相似度推翻字段约束。

新增默认关闭的 `MUSEUM_METADATA_ROUTING`，版本 `catalogue-author-date-v1`：

- 只读取馆方原文中独立的 `Maker` / `作者 Artist` 和 `Date` / `年代 Date` 行。正文提及不计为字段证据，不改原文。
- 作者采用完整姓名匹配，允许姓、名顺序交换及有限中文别名；同名多件保留多个候选。含工厂别名、归属不确定、否定或不支持的组合条件时沿用旧检索。
- 年代比较编目标注值：`1930`、`约1930`、`1930—1959` 分别处理，不把约数或范围当作精确年份，也不推断区间重叠。
- 从全库字段索引取出匹配作品，原检索只决定这些作品的展示顺序；回查 active 状态和来源哈希后最多展示五件。Trace 保留匹配总数、截断状态及原始字段证据。
- 明确字段查找开启新作品选择，避免前一件作品或历史改写限制结果。跳过大模型改写、候选猜测和 BGE；仍让游客确认作品。
- 没有匹配时只说明当前编目没有符合条件的记录，不宣称真实博物馆没有该作品。显式选定作品、完整编号和图片检索继续原路径。

这是有限句式的字段路由，不是完整自然语言筛选器。例如“找乔瓦尼·博洛尼亚的作品”“找年代标注为1930的作品”可直达；“这件作品的作者是谁”、复杂多条件和宽泛外观描述仍走原问答或检索。中文别名尚不覆盖所有作者。

## 启用、复现与回滚

本机已设 `MUSEUM_METADATA_ROUTING=true` 并重启服务。公开默认 false；设回 false 并重启后端即可恢复前一版检索，无需迁移馆藏或清空数据库。原本机配置备份在 `.runtime/config-before-catalogue-metadata.env`，含密钥，不可提交。

已具备本地私有语料、上一轮冻结文件和依赖时，在仓库根目录执行：

```powershell
$env:PYTHONPATH='backend'
.venv/Scripts/python.exe scripts/evaluate_catalogue_metadata.py --output eval/private/new-metadata-replay.json
.venv/Scripts/python.exe scripts/check_catalogue_metadata_live.py --output eval/private/new-metadata-live.json
.venv/Scripts/python.exe -m pytest backend/tests -q
```

离线脚本核对语料及模型版本，引用上一轮固定文件；接口脚本读取本轮固定 `catalogue-metadata-v1.json`，依赖本机服务与 MongoDB。输出拒绝覆盖，接口不自动重试；两脚本不需要付费模型调用。原题、字段内容、候选和 Trace 仅在 `eval/private` 保留；公开代码、合成测试和[脱敏汇总](catalogue-metadata-results.json)不包含私有馆方原文。公开克隆无法复现私有数据分数。

下一项单独诊断 BGE 的 CPU 时延和超时回退。此次只是让明确字段查询绕过不需要的重排，尚未修复普通自然语言查询的 BGE 超时；局部／背面识图保持独立评测。
