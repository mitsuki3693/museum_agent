# BGE 时延、恢复与图片可用性

日期：2026-10-10。本轮范围为文字重排性能与故障恢复，AIC 缺图单独处理。普通问答的生成／事实核验及局部识图未改动。

## 固定输入与诊断

同一千件库冻结 134 条开发查询，其中 107 条实际进入 BGE，其余通过名称／作者／年代等路由处理。固定原有 BM25F、MiniLM、词表、来源及候选证据；没有改变 gold，也没有增加馆藏。重排最多接收 25 件候选，不是全部 1,012 条记录。

`benchmark_rerank_latency.py` 记录启动校验与加载、证据组装、分词、每批推理、JSON 管道往返和首次请求。`profile.evidence_ms` 包含证据分词时间；`evidence_assembly_ms` 才是扣除分词后的时间，避免重复加总。`exchange_overhead_ms` 是服务总耗时减 worker 内部耗时的余量，不是网络延迟。

原版 12 题 × 3 轮、另 1 次预热：P50 6.833 秒，P95 8.100 秒，2/36 次超过 8 秒；平均约 99.37% 的服务时间属于模型推理。启动另计：校验约 1.54 秒，模型加载约 6.73 秒，合计约 9.79 秒。诊断允许原版慢请求完成以观测耗时，网站 8 秒上限没有提高。

## 逐项实验

1. **保护候选再缩减。** 保留原回退前五、词法与向量通道首位及标题明确命中，再按原融合顺序补足。明确编号、作者、年代先在上游直达。Top8/12/16 都令一条原本在 25 候选内的旧 gold 消失，故不接网站；不因该题标签可能不穷尽就删掉它。标题保护溢出时保留全部保护项，没有伪称每次都压到预算内。
2. **证据预算。** 192 tokens 的全候选组装检查未丢失原先保留的关键字段及命中段落；160 tokens 在 6 条查询、6 个候选上发生丢失，故排除 160。INT8 的 12 题 192/256 对照中 gold 名次未变化，但没有对 192 完成全题排序验收。最终继续保留 256，不为额外提速损失上下文。
3. **ONNX 与动态 INT8。** 从已有哈希校验的 BGE 权重本地导出，固定原分词器、全部候选、批次及原始证据。FP32 与 INT8 分开对比；INT8 初轮出现排序变化，因此继续完成全题检查。详见[脱敏汇总](rerank-latency-results.json)。

ONNX FP32 小样本计时期间有一段回归测试重叠，不能作为干净的最终延迟结论。最终 36 次 INT8 服务验收已单独运行。全题质量回归中的复用基线明确标记 `reused`，不计为新增性能测量。动态量化只作用于指定 MatMul/Gemm 权重，嵌入等仍保留浮点，不能声称整个模型变成四分之一大小。

## 最终对照

保留最多 25 候选、256 tokens，只切换为 ONNX Runtime 动态 INT8。

| 指标 | 原 PyTorch FP32 | ONNX INT8 |
| --- | ---: | ---: |
| 107 条实际重排查询中有 gold 的查询 | 103 | 103 |
| gold 在 Top1 | 91/103 | 91/103 |
| gold 在 Top5 | 100/103 | 100/103 |
| MRR@5 | 0.9243 | 0.9256 |
| 12 题各 3 轮，重排 P50 | 6.833 秒 | 2.827 秒 |
| 同组重排 P95（最近秩） | 8.100 秒 | 3.422 秒 |
| 超过 8 秒 | 2/36 | 0/36 |

旧版是 worker 服务计时，新版是实际 HTTP 请求中同一重排阶段的计时，均不含首次加载；固定相同 12 题、候选及原文。不是整段 DeepSeek 问答延迟。原版使用 30 秒诊断等待以看清慢请求，实际网站硬上限仍为 8 秒；INT8 36 次验收始终用 8 秒。

质量检查验证全部候选身份和每条输入证据哈希一致。没有新增 Top5 漏召回；但 `old-G01` 由 2→3、`paraphrase-lilies` 与 `dev-chair` 由 1→2，不能写成排序完全不变。只有 25/107 条前五顺序完全一致，53/107 条前五集合相同。原有三个 gold 未命中仍保留；部分旧标签不穷尽，未修改答案集合来提高成绩。另 4 条无 gold 的查询仅检查输入与排序，不算对错。

逐次读取到的最大进程 RSS 约为 FP32 3,024 MiB、INT8 1,229 MiB，是采样观测值，不是峰值内存测试。耗时和内存都仅代表本机顺序回归。

实现参考：[Optimum 动态量化文档](https://huggingface.co/docs/optimum-onnx/en/onnxruntime/usage_guides/quantization)、[BGE 官方模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)。本项目用本地 PyTorch 导出与 ONNX Runtime 量化，未引入另一个远端模型。

## 自动恢复

旧实现一次超时会一直停用 BGE。新增独立开关 `MUSEUM_RERANK_AUTO_RECOVER`：当前请求终止 worker 并立即回退；1 秒后后台重新加载，加载期间新请求直接回退。连续三次失败进入 30 秒冷却；只有一次实际重排成功才清零失败计数。启动失败也受同样冷却约束，单次加载保留原超时限制。

没有重新执行失败的用户请求，没有排队等待模型加载，也没有为用户偷偷重试生成。健康检查报告后端、预算、恢复状态和计数。关闭应用会取消恢复任务；Windows worker 加入专属 Job Object，结束时同时清理它启动的子进程，避免只结束虚拟环境启动器。

最小回归 `test_timeout_recovers_worker_without_restarting_site` 修复前失败，修复后通过；另覆盖连续故障冷却、恢复中关闭、后端不匹配拒绝及 Windows 孙进程清理。

真实 HTTP 故障注入将一次等待期限设为 1ms：681ms 内返回与原 RRF 完全相同的结果；重载期间下一请求 388ms 回退。随后 worker 自行重启一次，下一查询成功应用重排，失败计数清零，网站进程未重启。此项验证恢复流程，不是常态 8 秒超时会在 681ms 内完成。完整编号、作者、年代三个直达请求均绕过模型，未调用 DeepSeek。36 次性能请求、故障注入均使用隔离内存库。

接入实际 `.env` 时额外发现整数 Literal 不接受环境文件字符串的启动问题；先复现三条失败，再增加允许值解析，仍拒绝未批准的 512 tokens。算法输出不变。

## 本机接入验收

本地配置已切换 `int8`、256 tokens、自动恢复开启，实际健康检查为 ready、8 秒期限；MongoDB 和既有千件语料保留。13 条真实网页代理字段查询全部通过，Trace 从 MongoDB 读回，零 LLM 调用；另检查幂等请求与冲突拒绝。454 项后端回归通过，保留一条既有 Starlette 弃用警告。

同一中文外观查询在两个新会话各运行一次，两次均返回目标候选。首次实际重排为 7.380 秒、网页请求合计 9.918 秒；预热后分别为 3.890 秒、6.145 秒。每次有一条 DeepSeek 意图判断 usage 记录。冷启动与热态分开记录，不能将 3.422 秒的隔离重排 P95 写成所有网页请求都在此时间内完成，也不把这两次找作品当作开放式问答验收。

107 条配对结果以两批存入本地 `eval_runs`，80＋27 条读回一致，标记 `human_reviewed=false`、`online_ab=false`。公开摘要仅含聚合指标、开发用例编号和证据哈希；原始输入、馆藏正文、Trace、模型与导出权重继续仅本地保存。

后续顺序：普通问答的改写／生成／核验计时与字段直答 → 局部识图固定 20 张库内＋10 张库外对照。此次没有关闭事实核验，也没有修改图片识别阈值。

## AIC 图片状态

官方 API 对 `artic-6565 / American Gothic` 返回图片编号，但 `is_public_domain=false`。[官方记录接口](https://api.artic.edu/api/v1/artworks/6565?fields=id,title,image_id,is_public_domain)

本轮未下载该图，记录 `image_status=missing`、`image_reason=not_public_domain`。前端保留缺图说明和馆方链接。对象接口同时检查本地图片文件存在及路径范围，不再仅凭 image_id 返回一个可能 404 的地址。数据检查结果为：1,003 件有本地展示图片，1 件受当前开放授权策略限制，8 件未进入图片清单。

AIC 导入器以后会请求图片与许可字段，并生成本地可用性状态；本轮没有重跑馆藏导入，语料哈希保持不变。可独立运行 `scripts/audit_collection_images.py` 检查当前语料。目录占位和数据状态不属于图像识别算法优化。

## 复现与回滚

可选实验依赖在 `requirements-rerank-onnx.txt`，大模型权重和原始评测仅本地保存。公开仓库默认仍为 PyTorch、256 tokens、自动恢复关闭。模型切换与自动恢复是独立开关；设回 `MUSEUM_RERANK_BACKEND=torch` 可恢复原后端，不改变图库或 MongoDB。

在已具备本地私有数据和模型的环境中，设置 `PYTHONPATH=backend;scripts` 后使用：

- `benchmark_rerank_latency.py freeze`：冻结真实候选请求；输出必须为新的 `eval/private` 文件。
- `evaluate_rerank_pool.py`、`evaluate_rerank_budget.py`：候选覆盖与关键证据保护检查。
- `prepare_reranker_onnx.py --output models/<新目录>`：校验原权重后导出，拒绝覆盖。
- `compare_rerank_backends.py --backend torch|onnx|int8 --budget 192|256 --scope probe|full --output eval/private/<新文件>`：固定输入的排序对照。
- `check_rerank_latency_http.py --backend <后端> --budget <预算> --output eval/private/<新文件>`：独立本机 HTTP、真实模型、36 次请求与故障恢复，使用内存测试库，不写用户数据库、不调用 DeepSeek。

这套题是开发回归，不是人工审核游客盲测，也不是线上 A/B。P95 针对明确说明的本机顺序任务，不代表高并发或完整问答 SLA；普通问答仍需单独衡量查询改写、生成和事实核验。
