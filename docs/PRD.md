# 馆语 PRD v0.3 — 游客入口调整

更新：2026-09-29。替代旧版 Coze 路线。交付方式：Codex 辅助代码开发、GitHub 留档、本地可运行作品；预算上限约 300 元，目标 10 月 8 日投递前形成可演示案例。

## 用户与业务场景

1. 在展品前拍作品或展签，确认后听一段简短讲解，再继续提问。
2. 不便拍照或不在现场时，通过作品名称、画面描述或示例卡片查找作品。
3. 产品维护者需要知道哪些回答失败、为什么失败、知识是否需要补充。

首版数据样本为芝加哥艺术博物馆 12 件作品。文化遗产实习背景用于解释需求来源；此独立开发项目不等于原实习已完成的系统。

## P0 用户任务与验收

| 功能 | 行为与失败处理 | 当前证据 |
|---|---|---|
| 选藏品 / 全馆检索 | 可选一件，或输入名称 / 画面描述 | API 及网页已实现 |
| 拍照确认 / 听讲解 | 本地预览、候选确认、通过核对后播放 | 代码与控制逻辑测试已实现；实拍和设备语音待验证 |
| 简明 / 深入讲解 | 相同事实约束，最多 2 / 5 条 | 简明讲解真实单题通过；条数上限回归通过，完整质量待评测 |
| 连续追问 | 最近 6 条消息用于改写；记录不当作官方依据 | 已实现；待真实 API 评测 |
| 引用原文 | 每条陈述绑定 source_id 与逐字 quote | 回归测试及真实单题链路通过，仍需人工金标准评测 |
| 答案复核 | 确定性引用检查后，再进行模型语义复核；每次改写均重新核对，最多 2 版 | 失败链路回归通过 |
| 资料不足 / 服务失败 | 明确提示，展示可查阅资料，不发布未核对草稿 | 测试通过 |
| 显式反馈 | 有帮助 / 事实有误 / 没有解答；可修改同条反馈，禁止跨会话操作 | 测试通过 |
| 维护者评审 | 单独凭据访问 trace、反馈并导出 | 代码已实现；不冒充馆方后台 |

## 技术选择及理由

Next.js 复用既有页面工程；FastAPI 复用 Python 检索和模型客户端。BM25 适合名称与编号，384 维多语言 MiniLM 向量辅助中文描述检索英文资料，RRF 融合排名。不增加神经重排和 pi 服务。

搜索字段按行拆分并按约 220 字符切短段、加作品标题。候选命中后按藏品去重，再回查有效原文，避免把生成摘要作为知识事实。模型只引用原始馆藏记录。

MongoDB 适配作为持久化目标；本机初次开发暂用内存模式并在页面明确说明。不存在自动无提示存储降级。

## 设计取舍

- 游客端以拍照入口为优先；识别不确定时让游客确认或补拍展签，名称搜索作为后备。
- 允许答不上来，避免知识不足时硬答；不承诺消除所有幻觉。
- 有效来源、逐字引用和模型复核分别检查。模型仍可能误判，需人工评测。
- 追问本身仅表示继续交流，不映射成负反馈或自动训练信号。
- 通过固定数据版本做离线对照，不能用不同知识库、不同题库的成绩宣称改进。
- 单进程限流与防重，作为本地试用保护；不声称支持万人在线。
- 密钥仅在服务端 .env，管理页凭据不存入浏览器持久存储。

## 非目标

馆方生产上线、文物真伪鉴定、实时导览路线、自动调节温湿度、长期记忆、情感陪伴、强化学习、自动灰度发布和多 Agent Swarm。

## 发布门槛

1. 无密钥路径可运行、状态真实、来源能打开。
2. 用户完成 40 题人工复核。
3. 配置 DeepSeek 后完成真实问答、追问、无依据拒答与反馈演示。
4. 将真实失败整理成至少 3 个可复现案例；不能凑写虚构指标。
5. 如使用 MongoDB，先验证重启后记录仍在及实际备份恢复。
6. GitHub 检查通过后标记可演示版本；本地测试不代替云端流水线成功。

## v0.3 需求修正及新增验收

用户指出“输入编号”不符合现场游客的自然行为。本轮从检索工具界面调整为拍照导览入口，保留已有证据检索后端。游客是否偏好拍照仍需真实用户验证，不把该假设写成调研结论。

- 摄像头 / 相册选择：本地预览，点击识别才上传。桌面相机选择器与手机相机行为由浏览器决定。
- 识别：支持作品或展签；两阶段模型处理输出白名单内候选；所有候选须游客确认，不自动认定。
- 错误恢复：模糊、无匹配、不在12件范围、服务失败分别提示；可以补拍展签或输入名称。
- 播放讲解：仅播放已经通过核对的回答；用户主动点击，可停止。
- 语音输入：浏览器支持时开放，识别文字可修改后发送；不支持或拒绝麦克风时仍可打字。
- 路线：目前无地图和实时展位，未实现，不以模型编造路线填充演示。

新增照片金标准应包括清晰作品、局部作品、反光、展签、同题材相似作品、馆外作品。当前只有控制逻辑的模拟测试，不存在真实识别准确率。
