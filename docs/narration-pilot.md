## 本轮产品决策

用户目标是看懂眼前作品。固定讲解适合快速收听；AI 用于按年龄、兴趣和时间调整表达，以及基于证据的追问。二维码、作品名称和拍照是定位同一件作品的不同入口，扫码不是需要被淘汰的旧方案。

建议链路：定位作品 → 查找经复核的标准讲解 → 默认直接展示／朗读 → 有个性化需求时基于底稿与馆方证据改写 → 沿用事实引用和复核 → 允许继续提问。

- 不要求每次基础讲解都调用模型；正式批准的标准稿可直接返回。当前程序尚未接入这一分流。
- 个性化改写不得新增无依据的年代、作者动机、人物对白或故事。儿童表达可用明确的比喻、观察邀请，不把想象说成史实。
- 追问超出底稿时仍可检索现有官方知识库；库中无依据则说明缺少资料。
- 图片识别只用于寻找库中作品，不能靠图片生成未经支持的历史故事。当前候选确认保留。
- 下一阶段界面收敛为聊天框：输入文字／照片，答案卡内播放讲解，来源折叠；不额外摆出模型、Agent、检索模块。此次暂不改前端。
- 路线规划、场馆拥挤度和实时运维不在本轮范围；目前没有可验证的实时场馆数据。

## 三件项目讲解底稿

下列是依据已入库的 Art Institute of Chicago 介绍重新编写的中文草稿，**不是馆方官方中文讲解词，也未经馆方审核**。对应机器可读文件为 `data/narration-library.draft.json`，保存来源哈希、事实对应依据及 `reviewed=false`。馆方 description 原许可 CC BY 4.0，改写需保留来源、许可及改动说明。

### 《卧室》／The Bedroom

这是梵高在1889年创作的《卧室》，描绘了他在法国阿尔勒“黄房子”里的卧室。同样的构图一共有三个版本，芝加哥艺术博物馆收藏的是第二版。鲜明的颜色、厚重的笔触和向后延伸的线条，可能让人感到有些紧张；不过，梵高希望这幅画传达的是平静与休息。你看着这个房间，会觉得放松，还是有点不安？

来源：<https://www.artic.edu/artworks/28560>。注意：1888年第一版与1889年本馆第二版不能混淆；不能把画面描绘地直接当作本版创作地。

### 《睡莲》／Water Lilies

这幅1906年的《睡莲》来自莫奈在法国吉维尼营造的水上花园。画家把注意力放在水面上：左下和右上的睡莲之间留出一条水路，树木和云朵倒映其中。他没有按照常见的方式把陆地、天空和水面分开描绘。你可以试着找一找，哪些是浮在水上的植物，哪些是水里的倒影。

来源：<https://www.artic.edu/artworks/16568>。注意：这里讲的是本馆1906年版本，不能把橘园美术馆壁画的年代和规模套过来。

### 《大碗岛的星期天下午》／A Sunday on La Grande Jatte—1884

修拉在这幅画里描绘了塞纳河畔不同年龄与阶层的人们。仔细看，人物和景物由并排的小色点与短笔触组成，这是他的点彩技法。画名里虽然有1884，作品并不是那一年就全部完成：本馆记录为1884至1886年，边缘后来在1888至1889年补上。你可以放大图片观察色点，再缩小看看它们如何组成完整的画面。

来源：<https://www.artic.edu/artworks/27992>。注意：画名年份不是完整创作日期；手机放大建议属于项目观察引导，不是馆方原话。

## 十道待人工复核问题

这是开发检查集，不是独立盲测，也不是已经通过的评测结果。先逐题确认预期，再冻结问题与底稿版本。

| ID | 已确认作品／问题 | 验收点 |
|---|---|---|
| N01 | 卧室：这幅画是谁画的，哪一年？ | 梵高，1889；不能回答本馆是1888年第一版 |
| N02 | 卧室：这张为什么看着有些紧张，是画家想表现焦虑吗？ | 区分观看感受与馆方记载的平静、休息意图，不捏造心理诊断 |
| N03 | 睡莲：这里的树和云是画在天空里吗？ | 根据原文说明水面的倒影，不机械把云都当作直接天空 |
| N04 | 睡莲：这幅是1906年的还是橘园里那组壁画？ | 明确当前本馆作品1906年，不混同别馆系列 |
| N05 | 大碗岛：为什么靠近看都是小点？ | 并置色点、短笔触和点彩技法；有对应来源 |
| N06 | 大碗岛：名字写1884，为什么说后来还在画？ | 创作1884–86；边缘1888–89；区分标题与创作跨度 |
| N07 | 卧室：给6岁孩子讲，用很容易懂的话 | 保留核心事实，去掉术语或解释术语；可问观察问题，不编造梵高与孩子的对白 |
| N08 | 睡莲：我赶时间，只想知道该看哪里，最多两句话 | 聚焦睡莲与倒影，满足长度和兴趣要求，不堆年代；不承诺未经朗读测量的秒数 |
| N09 | 大碗岛：画家当天跟画中小女孩说了什么？ | 说明现有资料没有这段对话，不编造故事；可转向有来源的画面说明 |
| N10 | 延续N07同一会话：那芝加哥这幅是三个版本中的哪一个？ | 指代仍是卧室，答第二版；不会因换表达风格而丢失作品身份 |

人工记录每题的实际回答、引用、事实是否正确、是否回应需求、易懂程度、根因、修复及复测结果。N10必须在N07之后执行。不要用模型自评分替代人工判断。

对照顺序：先用三件作品的固定标准稿作为A，再用同一来源、同一底稿、固定模型版本的个性化改写作为B；N07、N08重点检查个性化带来的可理解性与简洁性。事实题和追问题另行评测，不能混成一个总分。记录每次模型调用数、耗时及实际token；有真实随机分流用户前称“离线对照”，不称线上A/B测试。

## 照片演示与证据分类

可以用手机拍摄电脑上显示的官方公有领域作品图，不需要到馆才能进行第一轮流程验证。优先用上面三件已入库作品；随机找一件库外作品不应期待系统讲出其历史。

1. 先上传清晰原图，检查最基础的作品匹配。
2. 同一张图用手机拍屏，先正面，再增加少量倾斜或屏幕反光。
3. 最后用一张库外图片检查是否会拒绝强行匹配。

每种条件独立记录，不把同一张图的多个拍摄版本当成多件独立作品。建议首批3件×原图／正面拍屏／倾斜拍屏，加1张库外图，共10次观察；这只是小样本问题发现，不能据此宣称馆内识别准确率。

记录字段：作品ID、图片来源与许可、拍摄类别、预期候选、实际候选、是否需补拍、是否错误确认、识别耗时、讲解是否与确认作品一致。初期不把原始个人照片提交公开仓库；可公开无个人信息的演示图及明确的许可说明。

手机无需直接打开网页也能先验证图片链路：手机拍屏后传到电脑，使用“从相册选”上传。要完整验证“手机打开网页→相机→上传→讲解”，需让手机能访问电脑服务；手机里的127.0.0.1指手机自己，不能用电脑的这个地址。

当前前端已有 `input type=file`、`capture=environment`，倾向调用手机后置摄像头，具体选项依赖浏览器；支持JPG/PNG/WebP，暂不支持HEIC。用户确认iPhone和电脑可连接同一Wi-Fi后，已启动仅绑定电脑Wi-Fi地址的演示前端，后端仍只监听本机。电脑侧页面和代理健康接口已返回200；没有修改防火墙，iPhone实际连通性、相机与语音仍待验证。具体本机地址保存在本地 `docs/private/va-pilot-review.md`。

参考：<https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/capture>。这与调用 `getUserMedia` 实时视频流不同，不把两者的浏览器要求混写。
