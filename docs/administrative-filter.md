2026-10-07。新增 `administrative` 实验策略：仅从语义索引排除精确标签为馆藏编号、Object ID、尺寸、入藏信息、部门的行。作者、材质、年代、产地、名称、分类和正文完整保留；原文、关键词索引、完整编号直达不变。默认仍为 `original`，本机网页配置没有切换。

相对已否决的广泛过滤，窄过滤恢复了上轮的退化。但网页旧题 G05 也失去了广泛过滤带来的改善，回到原版未命中状态。比较必须以原版为基线，不能只用差方案夸大提升。

向量块数：网页配置 1,280 → 1,127；扩库 3,021 → 2,668，约减少 12%。本轮旧题检索 P50：网页配置 26.92 → 25.20ms，扩库 51.28 → 46.65ms。查询向量跨组共用，组内顺序轮转；不含生成、HTTP、图片和额外排名诊断，不是独立网页压测，也不宣称稳定的线上提速。

这些题仍是开发集；属性题统计已知有字段依据的正例是否出现，不把未标注候选判成错误，不是人工盲测准确率。尺寸、部门、入藏信息类查询尚未专项验收，不因本轮通过就默认开启。

## 基线波动及处理

第一次尝试直接复用完整索引的向量，严格基线检查在网页旧题 T14 中失败：第 4、5 名交换，正确作品的命中并未改变。该次运行停止，没有被计入结果。

单题探针比较“复用完整批次向量”和“按 filtered 文档集合独立编码”：最大向量差约 `8.07e-8`；独立编码复现了上一轮顺序。随后三个组都按实际应用的文档集合独立编码，保留固定模型、输入和参数。完成的两套原版／filtered 候选列表逐题与上一轮一致，没有放宽断言或删除坏题。

数值相近候选对分批计算可敏感，不能把微小顺序波动当语义收益。探针记录保存在本地 `eval/private/administrative-filter-baseline-probe-v1.json`。本轮未加入无依据的舍入规则或修改相似度阈值。

## 实现、验收与回退

- `semantic_chunks.administrative_view` 从原切块派生，保留切块 ID、正文和来源；跨多块的管理字段行整体排除，未知标签不删除。
- `MUSEUM_DENSE_VIEW=administrative` 是显式实验选项，只有 local 向量模式使用。若启用需重启重建索引；恢复 `original` 并重启即可回退。本轮实际 `.env` 未修改。
- Trace 记录 `dense_view=administrative`、`dense_view_version=administrative-filter-v1`。广泛过滤 `filtered` 仅为历史复现保留，不建议开启。
- 实际 `MuseumIndex.search` 对照：网页配置 82 条＋扩库 114 条＝196 条，候选列表与离线实验完全一致。未调用回答生成或浏览器，不等同于游客端到端验收。
- 新增派生字段及回退测试；全后端 **269 项通过**。没有修改图片识别、原始馆藏或应用默认检索策略。

脚本 `scripts/evaluate_administrative_filter.py`：无参数执行离线三组对照，`--verify-integration` 验证应用入口；需要本地私有语料和缓存模型。已有报告时拒绝覆盖。设置 `PYTHONPATH=backend` 后使用项目 Python 执行，全程无外部模型调用。
